## 4. Layer 2 — 멀티 에이전트 독립 분석

- **데이터/상태 (P1)**: 학생은 제출 5건(문제 1111–4444)이 있는데, 목록의 모든 행이 **"시작하기"**로 표시되고 "완료/진행" 배지·"다시 풀기"가 전혀 안 뜸. 즉 **C-02의 풀이 상태(solve_state)가 `writing_submissions`를 반영하지 않음**(`problem_attempts` 비어 있음 기반으로 추정). 결과로 "풀이 상태" 필터(#2)와 [[07-C-03]] 다시 풀기 모달 진입이 실데이터로 동작 불가. (검증: solve=solved 필터·제목 검색 모두 "시작하기"만 반환)
- **콘텐츠 (nit)**: 1페이지(최신순)가 전부 "54번 / 난이도 5"로 단조 — 데이터 분포 특성(난이도 상→5 매핑)일 수 있음.
- **UX/IA (양호)**: 필터·정렬·검색·페이지네이션 인지하기 쉬움. 총 건수 상하단 표기.
- **반응형 (양호)**: 360에서 컨트롤 래핑, 행 가독.
- **접근성 (양호)**: 탭·셀렉트·토글 라벨 존재.
- **적대적 검증**: "solve_state 미반영"은 3가지 방법(solve 필터/기본 목록/제목 검색)으로 확정. 단 "C-02 버그"로 단정하기보다 **풀이 상태 산출 데이터(problem_attempts) 결손/연동 갭**으로 표기(시드 데이터 한계일 수 있음 — 실제 제품 동작은 attempts가 채워질 때 재확인 필요).

## 5. 결론 — 개선안

### P1 (이번 주 안에)
- **풀이 상태 정합 확인**: `writing_submissions`가 있는 문제가 C-02에서 "완료/다시 풀기"로 보이도록 solve_state 산출(또는 `problem_attempts` 연동) 점검. 현재 학생은 제출했어도 항상 "시작하기"만 보여 [[07-C-03]] 다시 풀기 흐름에 진입할 수 없음. — 근거: Layer 2 데이터/상태. 영향: C-02 목록 + C-03 진입.

### P2 (여유 있을 때)
- 데이터 분포상 1페이지가 단조로우면 기본 정렬/추천 노출 개선 고려(선택).

> 참고: 시드 데이터(attempts 부재)에 따른 관찰일 수 있어, attempts가 있는 환경에서 재확인 권장. 코드 미수정.
