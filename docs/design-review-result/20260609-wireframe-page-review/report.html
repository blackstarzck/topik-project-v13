사용자 화면 35개 2레이어 디자인 리뷰

TALKPIK(TOPIK 글쓰기 학습 앱)의 사용자 화면을 docs/Wireframe/ 기준(SOT)으로 실제 브라우저로 띄워 캡처하고, ① SOT 정합 ② 다관점 분석 2레이어로 평가했습니다. 제품 코드는 변경하지 않았습니다.

대상 35화면(관리자 4개 제외) · 2026-06-09 · 본 보고서는 사용자 재검증 정정(쓰기 콘텐츠) 반영본입니다.

★재검증 정정 (가장 중요)

초기 리뷰에서 "쓰기 52·53·54 화면이 콘텐츠 결손으로 막혀 있다"고 보고했으나, 사용자 확인(“/writing/* 전부 정상”)을 받아 처음부터 다시 검증한 결과 이 규정은 틀렸습니다.

실제 쓰기 콘텐츠는 정상입니다. DB 실측: q53 published 47개 중 46개, q54 82개 중 81개가 rubric·answer_key·materials 완비. 실제 문제 id로 진입한 q53·q54 화면은 "불러오기 실패" 없이 정상 렌더됨을 브라우저로 확인.
제가 본 "차단" 화면의 진짜 원인 (정정된 발견).
  • 기본 문제 선택 버그 — getWritingProblem이 ?problem= 없을 때 ORDER BY 없이 .limit(1)로 골라, 직접 URL/딥링크 진입 시 임의의(하필 빈) 문제가 로드됨. 개발 DB에선 빈 시드 예시(2222/3333/4444)가 떠 "조건 불러오기 실패"가 보였던 것. (코드)
  • 빈 시드 예시가 published 상태 — 예시 placeholder 3개가 공개로 남아 있음(시드 데이터 정리 필요).
  • q52만 진짜 문제 — q52는 published가 1개뿐인데 그게 빈 placeholder라, 정상 문제로 진입할 수 없음(콘텐츠 1건 부재).

→ 정상 흐름(문제 목록·추천에서 실제 문제로 진입)에서는 쓰기 화면이 잘 동작합니다. 아래 표/발견은 이 정정을 반영했습니다.

‘주의’는 데이터/딥링크 조건부 또는 P2 경미 항목입니다. P1 3건은 서로 다른 3개 근본 원인(q52 콘텐츠·기본 선택 버그·X-16 하이드레이션)이며 일부 화면에 파급됩니다. 색상만으로 구분하지 않도록 숫자를 함께 표기했습니다.

2핵심 발견 (정정 반영)

P1  쓰기 기본 진입 시 빈 예시 문제 로드 (코드 + 시드)

문제 파라미터 없이 /writing/answer-writing-52처럼 직접 들어가면, 정렬 없는 .limit(1)이 빈 시드 예시를 골라 "조건 불러오기 실패 → 제출 차단"이 됩니다. 실제 문제로 진입하면 정상입니다. 조치: 기본 선택에 ORDER BY(최신/추천) 추가 + 빈 예시 문제 unpublish.

P1  q52 완성 문제 부재 (데이터)

q52는 공개된 문제가 1개뿐이고 그게 빈 placeholder라, 대시보드·추천(C-01·R-02)이 권하는 "52번"을 눌러도 실제로 작성할 수 없습니다. 조치: 조건/루브릭이 채워진 q52 문제를 1개 이상 공개.

P1  X-16 새 비밀번호 화면 하이드레이션 불일치 (코드)

"약 60분 후(HH:mm쯤) 만료" 시각을 서버 렌더에서 계산해 서버/브라우저 결과가 달라집니다. SOT가 이미 "SSR에서 만료 시각 계산 금지(마운트 후 표시)"로 규정 → 구현이 자기 규칙을 어김. e2e가 이 버그를 잡습니다(3뷰포트 실패).

P2  일관성·폴리시 (대부분 공통 한 곳 수정)

  • 페이월/구독(X-03·X-04) 화면 상단에 내부 코드 X-03/X-04가 사용자에게 노출.
  • 내 서재·PDF 미리보기(F-01·F-M1)에서 항목이 문제 11111111(원시 UUID)로 표시.
  • antd Alert의 message 폐기 경고(빈 예시 렌더 시), X-11 legacyBehavior Link 경고.
  • 피드백(E-01·E-02) 하단 CTA 5개(SOT는 주요1+보조3=4 이하), 로그인/가입 CTA 비활성 정책, 예시 문제 제목 이중 접두사.
  • C-02 목록의 풀이 상태가 제출 기록을 반영 못해(problem_attempts 비어 있음) "다시 풀기"·C-03 모달 진입 불가(시드 갭 가능).
정직성 모범 사례. 약관/개인정보(X-13·X-14)는 placeholder임을 숨기지 않고 외부 LLM 전송 가능성을 명확히 고지, 가입/알림/페이월은 미구현을 "준비 중"으로 정직 표기, 프로필은 회원 탈퇴 미지원을 고지 — 가짜 기능을 만들지 않았습니다.

4방법 & 캡처

  • 실제 dev 브라우저로 35라우트를 360/768/1280 캡처(106장). public=localhost, authed=127.0.0.1 + 재생성 세션.
  • 시드(비교리포트·라이브러리)는 앱 실제 흐름으로 생성 후 teardown 완료 — 기존 제출 5건 보존 확인.
  • e2e(pnpm test:e2e) = 92 통과 / 3 실패 / 2 스킵. 실패는 전부 X-16(실버그를 의도적으로 노출).
  • 증거 스크린샷은 PII 보호를 위해 gitignore — 본 보고서엔 미첨부.

5한계 / 정직성

  • 작성 방식: 멀티 에이전트 워크플로우가 세션 한도로 실패 → 메인 루프 단일 리뷰어가 작성. 독립 다중 에이전트 교차검증은 부분 적용.
  • 초기 오판 정정: "쓰기 콘텐츠 전반 결손"은 재검증으로 철회. 실제 콘텐츠 정상, 원인은 기본 선택 버그+빈 시드+q52 1건.
  • 미검증(UNVERIFIED-LIVE): E-02 문장 첨삭, 유료 본문(X-02/07), X-17 정상 경로, 각종 실패/대기 상태.
  • dev + mock 피드백 기준 — 실 운영/실 AI/실 결제와 다를 수 있음.
