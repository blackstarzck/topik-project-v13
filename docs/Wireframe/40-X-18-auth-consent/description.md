## 이 폴더가 필요한 이유

일반 이메일 회원가입은 A-01 회원가입 화면에서 약관/개인정보 동의 체크를 받을 수 있다.
하지만 Google 같은 소셜 로그인은 사용자가 외부 provider 화면을 거쳐 앱으로 돌아오며, 이 과정에서 앱의 A-01 약관 체크 UI를 반드시 지나지 않을 수 있다.

그래서 `/auth/callback` 이후 바로 대시보드로 보내지 않고, `/auth/post-auth`에서 필수 약관 동의 여부를 확인한다. 아직 동의하지 않은 사용자는 이 X-18 `/auth/consent` 화면에서 최신 필수 약관과 개인정보처리방침에 동의한 뒤 다음 단계로 이동한다.

이 화면은 법적 문서를 보여주는 공개 `/terms`, `/privacy` 페이지와 다르다. X-18은 이미 세션이 생긴 사용자를 대상으로, 서비스 진입 전에 필수 동의 기록을 남기는 보호 게이트다.

## Detailed Description

### 40 X-18 소셜 로그인 약관 동의

1
■ 동의 게이트 컨테이너

▣ 설명
• `/auth/post-auth`에서 필수 약관 미동의가 확인되면 진입하는 보호 화면이다.
• 사용자는 이미 Supabase Auth 세션을 가진 상태다.
• 화면은 서비스 이용 전 법적 필수 동의를 마무리하기 위한 중간 단계다.

▣ 제약 조건: 세션 없는 사용자는 이 화면을 정상 이용할 수 없으며, 인증 흐름에 따라 `/login` 또는 에러 처리로 돌아가야 한다.

▣ 예외: 필수 published 약관이 하나도 없으면 `/auth/post-auth`에서 이 화면으로 보내지 않고 다음 단계로 진행한다.

2
■ 안내 제목/설명

▣ 설명
• "서비스 이용 전 약관 동의가 필요합니다" 수준의 짧고 직접적인 메시지를 제공한다.
• 소셜 로그인이 완료되었지만, TALKPIK AI 서비스 약관 동의는 별도로 필요하다는 점을 설명한다.
• 일반 회원가입과 다른 이유를 사용자가 이해할 수 있게 한다.

▣ 제약 조건: Google provider의 access token, raw OAuth error, 내부 DB id는 화면에 노출하지 않는다.

▣ 예외: 없음.

3
■ 미동의 문서 목록

▣ 설명
• `legal_documents.status='published'`이고 `requires_consent=true`인 최신 필수 문서를 기준으로 한다.
• 사용자별 `user_consents`에 없는 문서만 보여준다.
• 문서 유형은 현재 `terms`, `privacy`를 기준으로 한다.

▣ 제약 조건: 이미 동의한 문서를 중복 동의 대상으로 보여주지 않는다.

▣ 예외: 문서 조회 실패는 사용자를 조용히 통과시키지 않고 오류 상태로 처리해야 한다.

4
■ 필수 동의 체크박스

▣ 설명
• 사용자가 표시된 모든 필수 문서를 확인했고 동의한다는 단일 체크박스를 제공한다.
• 체크하지 않으면 계속 버튼 제출 후 `error=required` 상태로 되돌아온다.

▣ 제약 조건: 체크박스는 키보드와 스크린리더로 조작 가능해야 한다.

▣ 예외: 없음.

5
■ 계속 버튼

▣ 설명
• 체크된 상태로 제출하면 누락된 필수 동의만 `user_consents`에 기록한다.
• 기록 후 `next` query의 안전한 상대 경로로 복귀한다.
• 기본 복귀 경로는 `/auth/post-auth?intent=login`이다.

▣ 제약 조건: 외부 URL 또는 위험한 `next` 값으로 redirect하지 않는다.

▣ 예외: `next`가 유효하지 않으면 안전한 기본 경로를 사용한다.

6
■ 오류/재시도 안내

▣ 설명
• 체크박스 없이 제출하면 사용자가 무엇을 해야 하는지 짧게 알려준다.
• 서버 action이 같은 화면으로 되돌려 보내며, 사용자는 다시 체크 후 제출할 수 있다.

▣ 제약 조건: 오류 문구는 provider 내부 오류나 token 값을 노출하지 않는다.

▣ 예외: 없음.

## 화면 목적

소셜 로그인 사용자가 일반 회원가입 화면의 약관 체크 절차를 건너뛰는 경우에도, 서비스 진입 전에 필수 약관/개인정보 동의를 명시적으로 받고 저장한다.

## 분기

- 진입: `/auth/post-auth`에서 필수 published 약관 중 미동의 문서가 있을 때 `/auth/consent?next=...`로 이동.
- 이탈: 동의 기록 성공 시 `next` 경로로 복귀. 일반적으로 `/auth/post-auth?intent=login` 또는 `/auth/post-auth?intent=sign-up`.
- 세션 없음: 보호 route이므로 세션 없는 사용자는 정상 동의 대상이 아니다.
- 동의 완료: `/auth/post-auth`가 다시 학습 목표 존재 여부를 확인하고 `/onboarding/learning-goal` 또는 `/dashboard`로 보낸다.

## 피드백

- 필수 동의가 필요한 이유를 숨기지 않는다.
- 사용자가 체크하지 않으면 "필수 약관에 동의해야 계속할 수 있습니다" 수준의 안내를 제공한다.
- 이미 인증이 끝난 상태라도, 약관 동의 전에는 서비스 핵심 화면으로 진입시키지 않는다.

## 예외 상황

- 필수 published 약관이 없으면 `/auth/post-auth`에서 서버 로그를 남기고 이 화면을 건너뛴다.
- `next`는 상대 경로만 허용한다.
- DB 저장 실패 시 동의가 된 것처럼 처리하지 않는다.

## Navigation

- 진입 경로: `/login` 또는 `/sign-up`의 Google OAuth → `/auth/callback` → `/auth/post-auth` → X-18.
- 이탈 경로: 동의 완료 → `/auth/post-auth` → A-03 학습 목표 설정 또는 B-01 홈 대시보드.
- 관련 공개 문서: X-13 `/terms`, X-14 `/privacy`.
