# X-06 비밀번호 재설정 화면 데이터 계약

## 화면 요약
사용자가 이메일을 입력해 비밀번호 재설정 메일을 요청하는 화면이다.

이 문서는 사용자 화면이 소비하는 운영/관리 대상 데이터만 정리한다. 관리자 전용 화면 구현이나 관리자 스키마 확장은 이번 범위에 포함하지 않는다.

## 사용자 화면 표시 데이터
- 재설정 안내
- 이메일 입력
- 메일 발송 완료 메시지
- 로그인으로 돌아가기 링크

## 사용자 입력/상태 데이터
- 이메일
- 메일 발송 요청
- 재전송 선택

## 운영/관리 대상 데이터 계약
| 데이터 | 분류 | 확정 계약 | 메모 |
| --- | --- | --- | --- |
| 재설정 메일 요청 | DB 계약 없음 | resetPasswordForEmail은 Supabase Auth 흐름이며 public schema 테이블에 저장하지 않는다. | 메일 토큰은 Auth 내부에서 처리한다. |
| 재전송 제한/감사 이력 | 스키마 보강 필요 | 사용자별 재전송 횟수나 감사 이력을 앱 public schema에 저장하는 구조는 없다. | 보안 정책이 필요하면 별도 ledger가 필요하다. |

## Supabase 테이블 스키마 정보
현재 public schema migration에서 이 화면 전용 테이블/RPC/storage 계약은 없다. Supabase Auth 또는 정적 콘텐츠 흐름은 앱 DB 계약과 분리한다.

## 저장/조회/이벤트 흐름
사용자가 이메일을 제출하면 Supabase Auth 재설정 메일 요청을 호출한다. 성공/실패 메시지는 화면 상태로 표시한다.

## RLS/권한 기준
- 비로그인 화면이므로 사용자 소유 public schema row에 접근하지 않는다.
- 비밀번호 토큰은 Auth 내부에서만 처리한다.

## 스키마 정합성 메모
이 화면은 현재 DB 계약 없음으로 분류한다. 보안 감사 이력은 스키마 보강 필요다.

## 검수 필요 항목
- 재전송 제한 메시지와 시간 기준을 정한다.
- 존재하지 않는 이메일에 대한 응답 문구를 보안 기준에 맞춘다.
