## Detailed Description

### 1. 학습자 사이드 내비

▣ 설명

• 알림 설정 화면에서도 학습자 메뉴와 설정 위치를 유지한다.

▣ 제약 조건

• 설정 메뉴가 활성 상태로 보인다.
• 변경값이 존재하는 상태에서 다른 내부 링크로 이동하거나 새로고침/닫기를 시도하면 이탈 확인을 표시한다.

▣ 예외

• 수신 권한 또는 활성 채널이 없으면 설정 본문 상단에 권한/채널 안내를 우선 표시한다.

### 2. 알림 채널 탭

▣ 설명

• 이메일, Zalo, 둘 다 채널을 전환하고 연동 상태를 표시한다.

▣ 제약 조건

• 채널 탭은 3개 이하이며 한 번에 하나의 탭만 활성화한다.
• 미연동 채널은 실제 발송 가능 상태로 표현하지 않는다.
• 현재 구현 기준 Zalo는 수신 선호 저장은 가능하지만 실제 외부 연동/발송은 준비 중으로 표시한다.

▣ 예외

• 채널 미연동 또는 수신동의 없음은 탭 하단이나 상단 안내로 표시한다.
• 이메일과 Zalo가 모두 꺼져 있으면 리마인더 시간/요일 설정은 비활성 상태로 다룬다.

### 3. 알림 조건 입력

▣ 설명

• 리마인더 시간, 알림 주기, 마감/학습 리마인더, 피드백 완료 알림 조건을 설정한다.

▣ Paper 표시 항목

• 알림 주기 선택
• 알림 시간 선택
• 알림 내용 설정
• 시간대/권한 상태

▣ 제약 조건

• 시간은 `HH:mm` 형식으로 입력/표시한다.
• 요일은 0-6 범위의 정수로 저장한다. 현재 코드 주석 기준 0=일요일, 1=월요일이다.
• 조건 토글은 `weekly_summary`, `feedback_ready`, `study_reminder` 3개 키만 사용한다.
• 채널이 모두 off이면 스케줄 입력은 비활성화한다.
• 현재 구현의 기본 timezone은 `Asia/Seoul`이다.

▣ 예외

• 시간대 오류, 권한 없음, 설정 로드 실패는 해당 항목 또는 화면 상단에 표시한다.
• Paper에는 시간대/권한 상태 영역이 있으나, 현재 코드에는 사용자가 직접 timezone을 바꾸는 별도 컨트롤은 없다.

### 4. 미리보기/도움말

▣ 설명

• 설정한 알림의 실제 문구와 발송 시점 예시를 보여준다.

▣ Paper 표시 항목

• 알림 미리보기
• 도움말/마스코트
• 발송 이력 패널

▣ 제약 조건

• 미리보기 문구는 1개를 우선 표시한다.
• 예시 문구는 80자/2줄을 넘기지 않는 것을 기준으로 한다.
• 최근 발송 이력은 최대 5개를 보여준다.

▣ 예외

• 발송 이력이 없으면 빈 상태를 표시한다.
• 인앱 발송 이력은 `notification_delivery_attempts`를 기준으로 표시한다. 발송 이력이 아직 없는 계정에서는 빈 상태가 정상이다.
• 발송 실패 또는 미리보기 실패가 발생하면 재시도와 채널 설정 링크를 제공한다.

### 5. 저장 CTA

▣ 설명

• 변경한 알림 조건과 채널 설정을 저장하는 주 액션이다.

▣ 제약 조건

• 변경값이 없으면 비활성화한다.
• 저장 중 중복 클릭을 차단한다.
• 저장 성공 시 같은 화면에 머물며 완료 피드백을 표시한다.

▣ 예외

• 저장 실패 또는 권한 없음은 토스트와 항목별 오류로 표시한다.

## 구현 주의

- 인앱(in_app) 발송은 DB dispatcher와 pg_cron 기반 파이프라인까지 구현되어 있다.
- email/Zalo/push 외부 transport는 아직 구현되지 않은 deferred 범위다.
- 현재 사용자가 저장할 수 있는 것은 수신 선호, 채널, 리마인더 시간/요일, timezone 값이다.
- 문서나 UI에서 email/Zalo/push 외부 발송 완료처럼 아직 연결되지 않은 transport가 동작하는 표현을 쓰면 안 된다. 인앱 알림과 외부 transport 상태를 구분한다.
