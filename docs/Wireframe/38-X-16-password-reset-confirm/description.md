## Detailed Description

### 38 X-16 새 비밀번호 설정

1

■ 재설정 카드

▣ 설명

• X-06 비밀번호 재설정 요청 후 사용자가 이메일 링크를 열어 도착하는 confirm 페이지의 중앙 카드.
• Supabase recovery session이 있는 브라우저에서 새 비밀번호를 저장한다.

▣ 제약 조건: 카드 폭 360-520px, 모바일/데스크톱 동일 레이아웃.

▣ 예외: recovery session이 없거나 만료된 상태로 저장하면 실패 알림(#6)으로 전환.

2

■ 흐름 안내

▣ 설명

• 인증 흐름은 (1) `/password-reset` 요청 → (2) 이메일 링크 클릭 → (3) `/password-reset/confirm` 새 비밀번호 설정 두 페이지이며, Supabase 토큰 교환은 `/auth/callback`(`type=recovery`)에서 처리됨. 헤더 카피로 "마지막 단계"임을 안내함.

▣ 제약 조건: 별도 Stepper UI 미사용. 헤더 카피가 곧 위치 안내. (X-06 §2 Stepper 제거 결정과 정렬)

▣ 예외: 없음.

3

■ 비밀번호 입력

▣ 설명

• 새 비밀번호와 확인값을 입력하고 입력하는 동안 강도·규칙을 실시간 표시함.

▣ 제약 조건: 새 비밀번호 8-64자 필수, 규칙 실시간 검증(길이/영문 대소문자/숫자/특수문자 체크리스트 + 4단계 강도 바), 확인값 일치 검사. 길이는 가입(A-01)·재설정(X-06)과 동일한 8-64 정책.

▣ 예외: 불일치/길이 위반은 해당 필드 하단에 즉시 표시.

4

■ 안내 카피

▣ 설명

• 보안 조건(문자 조합 권장)과 링크 만료 시간을 설명함.

▣ 제약 조건: 만료 시간은 절대/상대 시간 병기("약 60분 후(HH:mm쯤)"). 정확한 발급 시각이 클라이언트에 없으므로 "약"으로 명시해 가짜 정밀도를 만들지 않음.

▣ 예외: SSR 단계에서는 만료 시각을 계산하지 않고(하이드레이션 mismatch 회피) 마운트 후 표시.

5

■ 마스코트

▣ 설명

• 보안 절차에서 느끼는 긴장감을 낮추는 보조 시각 요소.

▣ 제약 조건: 입력 영역을 가리지 않음(상단 배치), 대체 텍스트 필수. 래스터 이미지 미탑재 시 이모지(🔐) fallback.

▣ 예외: 이미지 로드 실패 시 이모지 fallback으로 대체.

6

■ 완료 CTA + 실패 알림

▣ 설명

• 새 비밀번호 저장(`supabase.auth.updateUser({ password })`) 또는 로그인 화면 복귀를 수행하는 최종 액션. 성공 시 다시 로그인해야 한다는 안내와 함께 A-02 로그인(`/login`)으로 이동.

▣ 제약 조건: 제출 중 CTA loading으로 중복 제출 차단. provider raw 오류 대신 `mapSupabaseErrorCode` canonical 문구만 노출.

▣ 예외: 저장 실패/링크 만료/세션 끊김은 동일한 warning 알림으로 묶고, 재시도(폼 재제출) + `/password-reset` 재발송 링크를 제공.

화면 목적 / 분기 / 피드백 / 예외 상황

목적

비밀번호 재설정 링크를 받은 사용자가 새 비밀번호를 안전하게 저장하고 로그인으로 복귀하게 한다.

분기

- 진입: X-06 재설정 메일 링크 → `/auth/callback?type=recovery` → redirect target `/password-reset/confirm`.
- 성공: `/login`.
- 실패: 현재 화면 유지 + 실패 알림 + `/password-reset` 재발송 링크.
- 세션/토큰 없음: 저장 시도가 실패하며 동일 실패 알림으로 안내.

피드백

- 성공: "비밀번호가 변경되었습니다. 다시 로그인하세요."
- 실패: "비밀번호를 변경하지 못했어요" 경고 + 재발송 링크.
- 입력 중: 비밀번호 강도/규칙 체크리스트, 불일치/길이 검증.
- raw auth error는 UI에 그대로 노출하지 않는다.

예외

- 만료된 링크, 끊긴 세션, provider 오류는 같은 recovery 안내로 묶는다.
- 브라우저 새로고침 후 recovery session이 사라질 수 있으므로 입력값 보존을 보장하지 않는다.
