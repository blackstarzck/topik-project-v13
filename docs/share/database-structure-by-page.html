사용 형태 (범례)

아래에서 각 화면이 데이터를 어떻게 다루는지 세 가지 색으로 구분합니다. 색만이 아니라 글자로도 표시되니 흑백 인쇄에서도 구분됩니다.

읽기

화면에 보여주려고 데이터를 가져온다.

쓰기

사용자의 행동으로 데이터를 새로 만들거나 바꾼다.

파생

원본 데이터를 모아 통계·점수·추세로 계산해 쓴다.

전체 그림

데이터는 크게 14개 묶음으로 나뉩니다. 각 묶음에 속한 테이블 이름과 한 줄 설명입니다.

공통 규칙

모든 화면에 똑같이 적용되는 약속입니다. 개별 화면 설명을 읽기 전에 먼저 이해해 두면 좋습니다.

계정 연결

모든 사용자 데이터는 로그인 계정에 1:1로 연결된 프로필을 기준으로 묶입니다. 프로필이 중심점입니다.

본인 데이터만 접근

사용자가 만든 데이터는 본인만 읽고 쓰도록 데이터베이스 차원에서 막혀 있습니다. 화면이 막아 주는 게 아닙니다.

제출본은 못 고친다 (불변)

쓰기 최종 제출본은 한 번 만들면 수정·삭제가 막힙니다. 다시 풀면 새 제출본을 만들고 이전 것과 연결만 합니다.

상태값은 정해진 단어만

대부분의 상태 컬럼은 미리 정해진 단어 집합만 허용합니다(상태값 모음 참고).

권한은 DB가 진실

관리자 여부·플랜·계정 상태 같은 민감한 값은 토큰이 아니라 DB에 저장된 값으로 판단합니다. 사용자가 임의로 못 바꿉니다.

첨부 파일은 별도 저장소

이미지·오디오·PDF 같은 파일 자체는 테이블이 아니라 파일 저장소에 두고, 테이블에는 위치만 둡니다.

화면별 데이터 구조

화면(IA 코드) 단위로 사용 테이블과 사용 형태를 정리했습니다. 처음 보는 테이블이 나오면 아래 테이블 레퍼런스를 함께 보세요.

인계 시 꼭 기억할 점

제출본·동의·관리자 기록은 못 고친다

이 세 가지는 "추가만" 되는 보존용 데이터입니다. 바꾸려 하지 말고 새 줄을 추가하세요.

본인 데이터 분리는 DB가 보장한다

화면에서 다른 사람 데이터를 걸러 줄 필요가 없습니다. 단, 우회 경로를 만들지 마세요.

공개 문제만 사용자에게 보인다

새 문제는 공개·검수 상태를 맞춰야 목록에 나옵니다.

관리자·조직 영역은 별도 앱 소유

사용자 앱에서 새로 만들거나 확장하지 않습니다. 스키마는 관리자 쪽을 먼저 따릅니다.

신규 코드 컬럼은 비어 있을 수 있다

문제의 주제 분류와 검수 진행 단계 컬럼은 코드 체계 확정 전이라 값이 비어 있을 수 있습니다. 값이 없다고 오류로 보지 마세요.
