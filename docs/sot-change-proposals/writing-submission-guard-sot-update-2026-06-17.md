# 2026-06-17 쓰기 제출 보안 보완 SOT 변경 제안

## 목적

이 문서는 TOPIK 쓰기 51~54번 제출 흐름에 새로 추가된 서버 검사를 SOT 문서에 반영하기 위한 변경 제안이다.

기존 SOT 문서를 직접 수정하지 않고, `docs/sot-change-proposals/` 아래에 별도 기록으로 둔다. 사용자가 SOT 수정을 확정하면 이 문서를 근거로 대상 SOT 문서를 갱신한다.

## 한 줄 요약

사용자가 제출 버튼을 눌러도, 서버가 마지막에 한 번 더 확인해서 공개되고 사용 가능한 쓰기 문제일 때만 답안을 저장한다.

## 왜 SOT 반영이 필요한가

이번 변경은 단순한 코드 정리가 아니라 제출 규칙 변경이다.

기존 문서에는 대체로 "제출하면 답안과 피드백 초기 데이터가 만들어진다"는 흐름만 적혀 있다. 하지만 현재 구현은 제출 직전에 서버에서 문제 상태를 다시 확인한다.

따라서 문서에도 다음 규칙이 들어가야 한다.

- 숨김 문제는 제출되지 않는다.
- 비공개 문제는 제출되지 않는다.
- 비활성 문제는 제출되지 않는다.
- 쓰기 문제가 아니면 제출되지 않는다.
- 사용자가 푸는 문항 번호와 실제 문제 번호가 다르면 제출되지 않는다.

## 현재 반영된 곳

| 구분 | 상태 | 설명 |
| --- | --- | --- |
| DB 변경 목록 | 반영됨 | 새 DB 변경 파일이 `supabase/migrations/INDEX.md`에 기록되어 있다. |
| 실제 제출 처리 | 반영됨 | 제출 저장 전에 서버가 문제 상태를 다시 확인한다. |
| 사용자 오류 안내 | 반영됨 | 제출할 수 없는 문제이면 "현재 제출할 수 없는 문제입니다. 다른 문제를 선택해 주세요."라고 안내한다. |
| 전체 데이터 사용 정리 문서 | 반영 필요 | 제출 전 서버 검사 규칙이 아직 빠져 있다. |
| 51~54번 쓰기 화면 문서 | 반영 필요 | 각 화면의 제출 조건에 새 서버 검사 규칙이 빠져 있다. |
| 제출 확인 모달 문서 | 반영 필요 | 제출 실패 이유에 "문제 상태 변경"이 아직 구체적으로 적혀 있지 않다. |

| 대상 문서 | 수정 이유 | 수정 방향 |

| `docs/Wireframe/10-D-03-long-form-writing-53/` | 53번 작성 화면의 제출 조건에 새 서버 검사가 빠져 있다. | 51번과 같은 기준을 추가한다. |
| `docs/Wireframe/11-D-04-essay-writing-54/` | 54번 작성 화면의 제출 조건에 새 서버 검사가 빠져 있다. | 51번과 같은 기준을 추가한다. |

## 사용자에게 보이는 변화

대부분의 정상 사용자는 변화를 느끼지 않는다.

하지만 사용자가 화면을 열어둔 사이에 운영자가 문제를 숨기거나 비공개/비활성 상태로 바꾸면, 사용자는 제출할 때 다음 안내를 보게 된다.

> 현재 제출할 수 없는 문제입니다. 다른 문제를 선택해 주세요.

이 경우 답안은 저장되지 않는다.

## 관리자가 이해해야 할 변화

운영자가 문제를 숨기거나 비활성화하면, 이미 화면을 열어둔 사용자도 그 문제를 제출할 수 없다.

즉, 운영 화면에서 문제 상태를 바꾸는 일은 단순히 목록에서 숨기는 것뿐 아니라, 제출 저장 가능 여부에도 영향을 준다.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 사용자 화면에서만 막기 | 채택하지 않음. 사용자가 직접 요청을 바꾸거나 오래된 화면에서 제출할 수 있으므로 서버 검사가 필요하다. |
| 문제 목록 조회만 강화하기 | 채택하지 않음. 목록에서 보이지 않아도 이미 열린 작성 화면에서는 제출 시도가 가능할 수 있다. |
| 제출 서버에서 한 번 더 확인하기 | 채택. 최종 저장 직전에 확인하므로 가장 확실하다. |

## SOT 갱신 시 권장 문구

아래 문구를 각 작성 화면 또는 제출 확인 모달 문서에 맞게 짧게 반영한다.

> 제출 시 서버는 문제 상태를 다시 확인한다. 공개/사용 가능 상태가 아니거나 쓰기 문제가 아니거나 문항 번호가 맞지 않으면 제출을 저장하지 않고 오류를 표시한다.

## 검증 메모

- 쓰기 제출 서버 검사 코드가 추가되었다.
- 제출 불가 문제일 때 사용자에게 보여줄 한국어 오류 안내가 추가되었다.
- 관련 단위 테스트와 통합 테스트는 통과했다.
- 미완료 검증은 "로컬 Supabase DB에 새 DB 변경 파일을 실제로 적용해 보는 확인"이다. Supabase 로컬 DB는 Docker Desktop Linux engine이 필요하지만, 현재 실행되지 않아 이 확인만 완료하지 못했다.
- 따라서 구현, DB 변경 파일 작성, 테스트 통과는 완료된 상태이고, 남은 것은 로컬 DB 적용 확인이다.

## 다음 단계

1. 사용자가 SOT 수정을 확정한다.
2. 이 문서를 기준으로 대상 SOT 문서를 갱신한다.
3. 갱신 후 `docs/Wireframe/data-usage-index.md`의 함수 수와 보조 기능 목록을 다시 맞춘다.
4. 51~54번 작성 화면과 제출 확인 모달 문서의 제출 실패 조건이 같은 말로 정리되어 있는지 확인한다.
