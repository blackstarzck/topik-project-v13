# 기관 초대 알림 만료 표시 정책 제안

- 제안일: 2026-07-13
- 상태: 구현 기준 제안서 (active SOT 승인 대기)
- 범위: 사용자 앱의 기관 초대 알림 목록과 기관 초대 모달

## 목적

기관 초대 알림을 확인할 때 사용자가 초대의 유효기간을 즉시 이해할 수 있도록 알림 목록에는 D-day를, 모달에는 만료일과 현재 상태를 표시한다. 만료된 초대는 수락할 수 없다는 상태도 같은 흐름에서 명확히 전달한다.

## 데이터 계약

- 기관 초대 알림 payload의 canonical field는 `expires_at`이다.
- `expires_at`은 ISO 8601 UTC timestamp로 전달한다.
- v13 사용자 앱은 payload의 값을 표시용으로 정규화하며, 만료기간을 `created_at`에 임의로 더해 추정하지 않는다.
- v13 범위에서는 새 table, migration, service-role API, admin RPC를 추가하지 않는다.

## 상태 계산 및 표시 규칙

- `expires_at <= now`이면 만료 상태로 처리한다.
- D-day는 `Asia/Seoul` 기준 calendar date 차이로 계산한다.
- 같은 날짜에 만료되는 초대는 만료 전까지 `D-0`으로 표시한다.
- 알림 목록은 기관 초대에만 `D-n` 또는 만료 라벨을 표시한다. 일반 알림에는 표시하지 않는다.
- 모달은 유효한 초대에 만료일을 locale formatter로 표시하고, 만료된 초대에는 만료 상태를 표시한다.
- payload의 만료 시각이 없거나 유효하지 않으면 D-day·만료 상태를 추측해 표시하지 않고 기존 초대 흐름을 유지한다.
- RPC가 반환한 최종 초대 상태가 있으면 해당 상태를 우선하며, 만료 상태에서는 수락 동작을 비활성화한다. 닫기 동작은 유지한다.

## 수용 기준

1. 미래 만료일 기관 초대 알림에 목록 D-day가 표시된다.
2. 만료된 기관 초대 알림에 만료 상태가 표시된다.
3. 기관 초대 모달에 locale 형식의 만료일이 표시된다.
4. 만료된 기관 초대 모달에서 수락 버튼은 비활성화되고 닫기는 가능하다.
5. 일반 알림에는 기관 초대 만료 표시가 노출되지 않는다.
6. 만료 시각이 없거나 잘못된 기관 초대는 기존 흐름을 유지한다.
7. desktop/mobile Playwright E2E로 유효·만료 상태와 모달 상호작용을 검증한다.

## 검토한 대안

- `created_at + 고정 기간`: 실제 초대 만료 계약을 반영하지 못하므로 사용하지 않는다.
- v13 DB에 만료일 저장: 초대 생성/관리 권한이 있는 시스템의 계약과 중복되므로 사용하지 않는다.
- 수락 RPC 계약 변경: 현재 작업은 표시와 사용자 동작 제한 범위이므로 확장하지 않는다.
