# 52번 쓰기 화면의 51번 구조 정렬 SOT 갱신 제안

## 대상 문서

- `docs/Wireframe/09-D-02-answer-writing-52/description.md`
- 필요 시 `docs/Wireframe/09-D-02-answer-writing-52/functional-spec.md`
- 필요 시 `docs/Wireframe/data-usage-index.md`

## 수정 이유

사용자 요청에 따라 52번 쓰기 화면은 51번 쓰기 화면과 같은 화면 구성과 코드 구조를 사용해야 한다. 현재 52번 SOT는 오른쪽 작성 도움말 영역에 조건, 가이드, 표현을 제공하는 흐름으로 읽히지만, 구현은 51번과 동일하게 답안 카드 하단에 표현 힌트 아코디언을 두고 오른쪽 패널은 guide/tips/hints 구조로 통일한다.

## 수정 방향

- 52번 답안 카드 하단에 `연결 표현` 아코디언을 표시하고, 표현 예시는 칩 형태로 제공한다고 명시한다.
- 오른쪽 도움말 패널은 51번과 같은 `guide`, `tips`, `hints` 3단 구조를 사용한다고 명시한다.
- 표현 예시는 오른쪽 세 번째 패널과 중복 표시하지 않고, 오른쪽 세 번째 패널은 빈칸별 역할/조건 힌트를 보여주는 영역으로 정리한다.
- route, 문제 유형, 답안 저장/제출, 10~160자 제한, `52.v1` 답안 JSON 계약은 변경하지 않는다고 명시한다.

## 결정 근거

- 51번과 52번은 모두 단문 빈칸 유형이며, 사용자는 두 화면의 화면 구성뿐 아니라 코드 구조까지 일치시키기를 요청했다.
- 이미 52번 locale에는 `expressionTitle`과 `expressionHint0~4`가 존재하므로 새 데이터 계약 없이 표현 힌트 아코디언으로 이동할 수 있다.
- 공통 스타일 `.writing-expression-accordion`, `.writing-expression-chip-list`, `.writing-expression-chip`이 51번에서 사용 중이므로 새 UI 스타일 토큰 없이 재사용할 수 있다.

## 검증 기준

- `/writing/answer-writing-52`에서 답안 카드 하단에 `연결 표현` 아코디언과 표현 칩이 표시된다.
- `/writing/answer-writing-52` 오른쪽 도움말 패널은 `guide`, `tips`, `hints` 키 구조를 사용한다.
- 자동 저장 끄기 버튼은 답안 카드 하단 표현 힌트 영역 안에서 계속 동작한다.
- 52번 답안 입력, 빈칸 탭 전환, 이탈 경고, 제출 확인, 분석/피드백 이동 흐름이 기존과 동일하게 동작한다.
- 51번 쓰기 화면의 기존 동작은 변경되지 않는다.
