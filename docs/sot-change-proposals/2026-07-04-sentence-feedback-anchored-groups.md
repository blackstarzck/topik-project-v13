# 문장별 첨삭 라벨: 위치 기반 → 답안 앵커 기반 그룹으로 변경

- 날짜: 2026-07-04
- 상태: 사용자 지시로 구현 (2026-07-04 세션, 원인 실증 후 진행)
- 관련 SOT: `docs/Wireframe/15-E-02-long-form-feedback/description.md`(문장 단위 첨삭, 5개 후 더보기), `docs/Wireframe/14-E-01-short-answer-feedback/`, `docs/metadata-tag-schema-rule.md` §7

## 배경 / 현상

- 53·54 피드백 페이지의 "문장별 첨삭"이 `서론, 본론, 본론, 결론`처럼 본론이 중복 표기됨.
- 51·52 피드백 페이지에 빈칸이 ㄱ/ㄴ 2개뿐인데 `ㄱ, ㄴ, ㄷ, ㄹ` 항목이 표기됨.

## 원인 (실 데이터로 검증)

1. 외부 채점 API(`GET /api/evaluation/{id}/feedback`)의 `annotations[]`는 **가변 개수의 인라인 첨삭**이며 서론/본론/결론·빈칸 구조가 없다 (`docs/swagger-api/schemas/evaluation.md` InlineAnnotationDetail).
2. `mapExternalEvaluationFeedback`(src/lib/writing-api/evaluation.ts)이 annotation을 배열 순서 그대로 `sentence_feedback` 행으로 저장한다. offset/category는 버려진다.
3. `SentenceFeedbackList`가 **행 순서만 보고** 라벨을 지어 붙였다: long은 첫=서론/마지막=결론/중간=전부 본론, short는 순번에 ㄱㄴㄷㄹ.
4. 실 DB 확인(2026-07-04, 개발 프로젝트): q53 제출 85258752… 은 첨삭 4행(그중 1행은 원문이 빈 문서 수준 조언), q51/q52 제출들은 2~4행("ㄱ:" 마커 텍스트 자체가 첨삭되기도 함). 행은 최초 동기화 이후 불변 — "리프레시마다 증가"는 재현되지 않음(동기화 route는 complete면 조기 반환).
5. `docs/metadata-tag-schema-rule.md` §7.2/7.3 기준 51·52 빈칸은 `blank_1`/`blank_2` 정확히 2개(ㄱ/ㄴ)다. 3개 이상 빈칸은 데이터상 불가능하다.

## 결정 (변경 내용)

문장별 첨삭 항목의 라벨을 "순서 기반 생성"에서 "**제출 답안 앵커 기반 그룹**"으로 바꾼다.

- 51·52: 답안(`ㄱ: …\nㄴ: …` 형식)의 각 줄에 첨삭 원문을 대조해 **ㄱ / ㄴ 그룹**으로 묶는다. 매칭 불가(빈 원문, 문서 수준 조언)는 **전체** 그룹.
- 53: `answer_json(53.v1).sections`(서론/본론/결론)에 대조해 **서론 / 본론 / 결론 그룹**으로 묶는다. 매칭 불가 → 전체 그룹.
- 54: 답안 문단(빈 줄 기준)을 첫 문단=서론, 마지막 문단=결론, 중간=본론으로 보고 대조. 문단 구조가 없으면 전부 전체 그룹.
- 그룹 헤더는 그룹당 1번만 표시하고, 그 아래 첨삭 카드를 나열한다(본론 첨삭이 3개면 "본론" 헤더 1 + 카드 3).
- 첨삭 5개 초과 시 더보기(기존 wireframe 제약 유지). 카드 수 기준으로 적용.

## Wireframe SOT와의 관계

- E-02의 "문장 단위 첨삭 / 5개 후 더보기" 제약은 유지된다(카드 단위 그대로, 더보기 유지).
- 바뀌는 것은 항목 라벨 표기 방식뿐: 순서로 지어낸 서론/본론/결론·ㄱㄴㄷㄹ 라벨 → 답안 실측 그룹 헤더. Wireframe 갱신 시 이 문서를 반영한다.

## 수용 기준

1. 51·52 피드백에서 그룹 라벨은 답안에 실재하는 빈칸 표기(ㄱ/ㄴ)와 전체만 나타난다. ㄷ/ㄹ 등 지어낸 라벨이 나타나지 않는다.
2. 53·54 피드백에서 서론/본론/결론 헤더는 각각 최대 1번만 나타난다. 어떤 섹션에도 못 붙는 첨삭은 "전체"로 표기된다.
3. 원문이 빈 첨삭(문서 수준 조언)은 서론/본론/결론/빈칸 라벨을 받지 않는다.
4. 첨삭 카드(Before/After/교정 이유 3열, 실패 폴백, 재분석 CTA) 동작은 기존과 동일하다.
5. PDF 내보내기(순번 표기)는 영향 없음.

## 검토한 대안

- 본론 1/본론 2 번호 부여: 중복 라벨 혼란은 줄지만 "본론"이라는 판단 자체가 여전히 순서 기반 추측이라 기각.
- 백엔드가 섹션별 첨삭을 반환하도록 변경: 근본적이나 v13 범위 밖(외부 API 소유 repo). 필요 시 별도 이슈로 제안.
- `annotations.category`를 라벨로 사용: 저장 스키마(`sentence_feedback`)에 컬럼이 없고 원격 DB 변경은 v13 범위 밖이라 보류.
