# 기관 초대 알림 모달 수락/닫기 UX 확정 제안

작성일: 2026-07-10

상태: 사용자 결정이 반영된 확정 제안

적용 대상: TALKPIK AI 사용자 앱(v13)의 기관 초대 알림 모달

## 1. 결정

- 기관 초대 알림 모달의 사용자 액션은 `닫기`와 `수락` 두 가지로 제공한다.
- 우측 상단 닫기 아이콘과 `닫기` 버튼은 모달만 닫는다.
- 닫기 동작은 초대 응답 RPC를 호출하지 않으며, 초대를 `declined` 상태로 변경하지 않는다.
- `수락` 버튼만 `respond_institution_invitation` RPC를 `p_accept: true`로 호출한다.
- v13 사용자 화면에는 `거부` 버튼을 노출하지 않는다.
- 모달 제목 `기관 소속 초대`는 유지한다.
- 본문 안내 문구에는 `word-break: keep-all`을 적용한다.
- payload에 기관 코드가 있으면 해당 코드를 표시하고, 코드만 누락됐으면 `코드 미확인`을 표시한다.
- 기관 코드 영역은 `font-size: 26px`, 가운데 정렬, 연한 토큰 배경색, 테두리 없음으로 표시한다.
- 알림 payload의 `code_label`은 계약 호환을 위해 유지할 수 있지만 모달에는 표시하지 않는다. 모달에는 `code`만 표시한다.

## 2. 기존 제안과의 우선순위

이 문서는 `docs/sot-change-proposals/2026-07-08-institution-invitation-modal-contract.md` 가운데 다음 UI 규칙을 대체한다.

- `수락/거부` 버튼 구성
- 사용자가 모달에서 직접 `p_accept: false`를 호출하는 흐름
- `code_label`을 모달 본문에 표시하는 규칙
- 유효하지 않은 초대에서 `수락/거부 버튼`을 비활성화한다는 문구

2026-07-08 제안의 다음 계약은 계속 유효하다.

- 기관 초대 알림 유형 판별
- 서버가 전달한 `invitation_id` 사용
- 초대 응답과 권한 검증을 RPC가 소유하는 구조
- `accepted`, `canceled`, 만료 및 오류 응답 처리
- 데이터베이스 migration과 RPC의 소유 경계

충돌하는 부분에는 이 문서의 `수락/닫기` 규칙을 우선 적용한다.

## 3. 상태 호환성

- 서버의 기존 `declined` 상태와 응답 해석은 과거 데이터 및 다른 호출 주체와의 호환을 위해 제거하지 않는다.
- v13 기관 초대 모달은 `p_accept: false`를 새로 발생시키지 않는다.
- 유효한 `invitation_id`가 있으면 표시용 `code`가 누락돼도 `코드 미확인`을 표시하고 수락할 수 있다. RPC의 신뢰 기준은 표시용 코드가 아니라 서버가 발급한 `invitation_id`다.
- 유효하지 않거나 이미 처리된 초대에서는 `수락`을 실행할 수 없게 하고, `닫기`는 계속 사용할 수 있어야 한다.
- 알림을 눌러 읽음 처리된 사실과 초대 수락 여부는 별개의 상태다. 모달을 닫아도 초대 응답 상태는 바뀌지 않는다.

## 4. 결정 이유

- `닫기`는 사용자가 결정을 미룰 수 있는 가역적인 행동이다.
- 별도의 거부 상태가 제품 흐름에 필수라는 근거가 없는 상태에서 즉시 거부 액션을 제공하면 오조작으로 초대를 되돌리기 어려울 수 있다.
- 서버의 `declined` 계약을 제거하지 않고 UI에서만 거부 진입점을 없애면 기존 데이터 호환성을 유지하면서 화면 동작을 단순화할 수 있다.

## 5. 검토한 대안

- 거부 버튼 유지: 닫기와 별도로 비가역적인 결정을 요구할 제품 필요성이 확인되지 않아 채택하지 않는다.
- `declined` 상태와 `p_accept` boolean 계약 전체 제거: 과거 데이터와 외부 호출 주체에 영향을 줄 수 있어 채택하지 않는다.
- 기존 2026-07-08 제안을 직접 수정: SOT 변경 이력을 보존해야 하므로 새 확정 제안으로 대체 범위를 기록한다.

## 6. 수용 기준

- 모달에 제목, 안내 문구, 기관 코드 또는 `코드 미확인` 대체 문구가 표시된다.
- `code_label`은 표시되지 않는다.
- 푸터에는 `닫기`, `수락`만 표시되고 `거부`는 표시되지 않는다.
- 닫기 아이콘 또는 `닫기` 버튼을 눌러도 초대 응답 RPC가 호출되지 않는다.
- `수락`을 누르면 `p_accept: true`로만 응답한다.
- `invitation_id`가 없으면 `수락`을 비활성화하고, `code`만 없으면 `코드 미확인`을 표시한 상태로 수락을 허용한다.
- 안내 문구는 한국어 단어 중간에서 임의로 줄바꿈되지 않는다.
- 기관 코드는 26px, 가운데 정렬, 연한 배경, 테두리 없음으로 표시된다.
- 기존 완료, 만료, 취소 및 오류 상태 안내는 계속 동작한다.
