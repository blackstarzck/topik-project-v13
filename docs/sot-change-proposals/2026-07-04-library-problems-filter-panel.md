## 변경 이유

선행 제안의 필터 카드 8종은 유형·분석 상태만 다뤘고, 문제 유형(51~54)·저장일·점수 기준으로 좁혀 보는
수단과 정렬·표시 방식 선택이 없었다. 사용자 요청(2026-07-04, 밀리의서재 검색 화면 참고)으로 검색 툴바
하단 카드 그리드를 **우측 필터 패널**로 대체하고, 정렬 Select와 리스트/카드 뷰 전환을 추가한다.

## 사용자 결정 기록 (2026-07-04)

| 질문 | 결정 |
| --- | --- |
| 정렬 UI 형태 | Select 드롭다운 (practice 목록과 동일 패턴, 모달 방식 기각) |
| 정렬 옵션 | 최근 저장 순(기본) / 오래된 순 / 점수 높은 순 / 점수 낮은 순 / 문제 유형 순(51→54) |
| 점수 범위 필터 기준 | 백분율(%) 슬라이더 — 유형별 만점(51/52=10, 53=30, 54=50)이 달라 절대 점수 기각 |
| 날짜 상세 검색 | 프리셋(1주일/1개월/3개월 이내) + 직접 범위(RangePicker) 병행, 기준 필드 `saved_at` |

검토한 대안: (a) 정렬 모달(밀리의서재 방식) → 신규 패턴 도입 대비 이득 없어 기각, (b) 절대 점수 입력 →
유형별 만점 차이로 혼동 여지가 있어 기각, (c) 날짜 프리셋만 → "상세 검색" 요구와 거리가 있어 기각.

## 제안 범위

### 우측 필터 패널 (선행 필터 카드 그리드 대체)

- 데스크톱(lg 이상): 목록 오른쪽 고정 `aside` 패널. 모바일/태블릿: 툴바의 `필터` 버튼(활성 필터 수
  Badge) → 우측 Drawer로 같은 패널 콘텐츠를 연다. Drawer 푸터는 `필터 초기화` + `결과 N건 보기`(닫기).
- 패널 그룹 4종:
  1. **문제 유형**: 51/52/53/54 체크박스. 양쪽 kind 모두 `question_no`로 판정한다.
  2. **항목 유형(트리)**: `저장 답안 > 분석 대기/중/완료/실패`, `저장 문제 > 제공 종료/이용 불가`.
  3. **저장일**: 프리셋 라디오(전체/1주일/1개월/3개월 이내) + RangePicker 직접 범위. 프리셋 클릭 시점에
     구체 from/to(그 날의 시작~끝)로 확정해 저장하고, 판정은 항상 from/to만 읽는다. RangePicker를 직접
     수정하면 프리셋 선택이 해제된다. 프리셋 확정 후 자정이 지나도 재계산하지 않는다(허용된 stale).
  4. **점수**: 0~100% range Slider(step 5). `scoreTotal/scoreMax` 백분율(경계 포함)로 판정하고,
     `[0,100]` 전체 범위는 비활성으로 정규화한다. 유형별 만점을 하드코딩하지 않고 저장된 `scoreMax`를
     쓴다. "분석 완료 답안 기준" 캡션을 함께 노출한다.

### 필터 결합 의미론 (선행 제안의 플랫 8종 OR을 대체)

- 그룹 4종은 **그룹 간 AND**로 결합한다. 빈 그룹 = 제약 없음.
- 항목 유형 트리는 **브랜치 합집합**: 하위 항목 체크는 부모 브랜치를 암묵 선택한다.
  - `submissionBranch = 저장 답안 체크 || 분석 상태 체크 존재`
  - `problemBranch = 저장 문제 체크 || 가용성 체크 존재`
  - truth table: `분석 완료`만 → 완료 답안만 / `분석 완료`+`저장 문제` → 완료 답안 ∪ 모든 저장 문제 /
    `저장 답안`+`분석 실패` → 실패 답안만(자식으로 좁힘).
  - 하위 항목만 체크된 부모 체크박스는 indeterminate로 표시해 브랜치 포함을 시각화한다.
- 문제 유형 그룹 활성 시 `question_no`가 null인 항목은 제외한다.
- 점수 그룹 활성 시 점수 없는 항목(저장 문제, 분석 전/실패, enrichment 미로딩)은 제외한다.
- 변경 근거: 선행 제안의 OR 합집합은 플랫 8종 카드에서는 예측 가능했지만, 날짜·점수처럼 축이 다른
  그룹까지 OR로 묶으면 "51번이면서 이번 달에 저장한 것" 같은 교차 조건을 표현할 수 없다.

### 패싯 카운트

- 체크박스 12종(유형4 + kind2 + 상태4 + 가용성2)에만 개수를 표시한다. 기준은 선행 제안과 동일하게
  **검색어 적용 후 · 패널 필터 적용 전** 집합이다. 날짜/점수 그룹은 카운트를 표시하지 않는다.
- 자기 그룹 제외(self-excluding) 카운트는 의도적으로 보류한다: AND 의미론에서는 더 정확하지만
  enrichment 비동기 도착 시 카운트가 이중으로 출렁이고 테스트 매트릭스가 배로 늘어난다. 클라이언트
  인메모리 집계라 필요 시 후속 제안으로 업그레이드할 수 있다.

### 정렬

- 툴바에 Select 드롭다운(기존 `ProblemListControls` 패턴): 최근 저장 순(기본, `saved_at` desc) /
  오래된 순 / 점수 높은 순 / 점수 낮은 순 / 문제 유형 순(51→54).
- 점수 정렬은 방향과 무관하게 점수 없는 항목을 뒤로 보낸다. 문제 유형 정렬은 `question_no` null을
  뒤로 보낸다. 동률 tie-break는 항상 최근 저장 순이라 enrichment 도착 전후에도 순서가 예측 가능하다.
- 파이프라인: `검색 → 필터 → 정렬 → 페이지네이션`. 정렬 변경 시 페이지는 1로 초기화한다.

### 리스트/카드 뷰 전환

- 정렬 옆 Segmented 아이콘 토글(리스트/카드). 기본은 리스트(기존 행 스타일 유지).
- 카드 뷰: 그리드(mobile 1열, sm 2열, xl 3열), `AppCard` 기반. 구성 = 유형·상태·점수 배지 / 제목
  (링크 규칙은 행과 동일: 분석 대기·중이면 링크 없음) / 요약 2줄 / 저장일 + 태그 + (저장 문제는
  다시 풀기 버튼). 비가용 문제의 흐림 처리(opacity)도 행과 동일하다.
- 카드 뷰에서도 `library-problems-mixed-row` testid와 `data-library-kind` 계약을 유지한다.
- 뷰 전환은 페이지를 유지한다.

### 상태 및 기타

- 필터·정렬·뷰 상태는 URL에 영속하지 않는다(선행 제안 결정 유지).
- 저장 항목이 하나도 없으면 패널·필터 버튼·정렬·뷰 토글을 모두 숨긴다.
- 빈 상태 우선순위는 `검색(emptySearch) > 필터(emptyFiltered) > 없음(emptyNoItems)` 유지. 필터 초기화는
  패널 전체(4그룹)를 한 번에 비운다.
- 분석 상태/점수 필터가 활성인데 enrichment가 아직 로딩 중이고 결과가 0건이면 `emptyFiltered` 대신
  로딩 스피너를 보여준다(0건 오탐 방지). enrichment 조회가 실패하면 점수 필터는 전부 제외된다.

## 데이터 계약

- 추가 DB 조회, 테이블, RPC 변경 없음. 기존 `library_items` 조회(`question_no`, `saved_at` 포함)와
  `writing_submissions.feedback_status` / `writing_feedback`(`score_total`, `score_max`) enrichment만
  사용한다.

## 알려진 제약

- 전역 `ConfigProvider`에 antd `locale`이 설정돼 있지 않아 DatePicker(RangePicker) 팝업 문구는 영문
  기본이다. 기존 `LibrarySubmissionsTab`의 RangePicker와 동일한 한계로, 전역 locale 배선은 별도 제안이
  필요하다.
- 날짜 프리셋은 클릭 시점 기준으로 from/to를 확정하므로 자정이 지나면 실제 "1주일 이내"와 미세하게
  어긋날 수 있다(재선택으로 해소).

## 수용 기준

- `/library/problems`는 `검색·정렬·뷰 툴바 + 혼합 리스트(리스트/카드) + 우측 필터 패널 + 페이지네이션`
  구조를 가진다. 선행 필터 카드 그리드는 제거된다.
- 데스크톱(lg 이상)에서 우측 패널이 보이고, 그 미만에서는 필터 버튼 → Drawer로 같은 패널이 열린다.
- 패널 4그룹(문제 유형/항목 유형 트리/저장일/점수)이 위 의미론대로 동작하고, 필터 변경 시 페이지가 1로
  초기화된다.
- 정렬 5종이 동작하고 점수 정렬에서 점수 없는 항목이 뒤로 간다.
- 카드 뷰 전환 시 그리드 카드가 렌더링되고 행 testid 계약이 유지된다.
- 필터 결과 0건이면 `emptyFiltered` + `필터 초기화`(전체 그룹 해제)가 보인다. 저장 항목이 전혀 없으면
  패널/필터 버튼이 렌더링되지 않는다.
- ko/en/vi 3개 로케일에 신규 문구가 존재한다.
- 기존 수용 기준(2026-07-01 제안: 검색/행 구성/페이지네이션)은 그대로 유지된다.
