# 기관 소속 전 학습 이력 보존 및 이후 문제 노출 정책 제안

작성일: 2026-07-01

상태: implementation brief

## 제안 요약

기관 초대 링크로 기존 일반 회원이 기관 소속에 연결될 때, 기존 학습 이력은 사용자 소유 기록으로 보존한다. 다만 기관 소속이 된 이후의 문제 탐색, 추천, 신규 제출, 다시 풀기는 현재 기관의 문제 노출 정책을 따른다.

## 정책 규칙

- 기관 연결 전 생성된 제출, 피드백, 비교 리포트, 라이브러리 기록은 삭제하지 않는다.
- 기관 연결 후 새 문제 탐색, 추천, 신규 제출, 다시 풀기는 `profiles.affiliation_code`와 `topik_writing_question_institution_exposure` 기준으로 현재 기관에 배정된 문제만 허용한다.
- 현재 기관에 배정되지 않은 기존 문제는 읽기 전용 이력으로만 접근 가능하다.
- 현재 기관에 배정되지 않은 기존 문제의 새 풀이, 재시도, 재제출은 허용하지 않는다.
- 이미 다른 기관에 소속된 계정은 자동 전환하지 않는다. v13 MVP에서는 다른 계정 로그인 또는 연결하지 않고 계속하기만 제공한다.

## 사용자 고지

`/auth/institution-invite` 화면에서 연결 전에 다음 취지의 안내를 노출한다.

- 기존 학습 기록은 보존된다.
- 기관 연결 후 새 문제 탐색, 추천, 제출, 다시 풀기는 현재 기관에 배정된 문제 기준으로 제공된다.
- 현재 기관에 배정되지 않은 기존 문제는 읽기 전용 이력으로만 접근 가능하며, 새 풀이 또는 재제출은 허용되지 않는다.

## 이번 구현 범위

- 사용자 앱 초대 화면에 정책 안내를 추가한다.
- feedback retry 가능 여부는 `is_writing_problem_visible_to_caller` 결과까지 확인한다.
- 저장 문제 library RPC의 `can_retry`와 문제 identity 노출은 현재 기관 visibility를 따른다.
- 원격 Supabase schema 적용은 v13 사용자 앱 작업 범위 밖으로 둔다.

## 제외 범위

- 기관 가입 시점 이력 ledger, 감사 로그 UI, 기관명 표시, 기관별 상세 약관, 관리자 승인, 기관 전환 self-service.
- 기존 제출/피드백/비교 리포트 삭제 또는 소유권 이전.
- admin app의 기관 코드 카탈로그, 만료, 초대 승인 정책.

## 검증 기준

- 기관 초대 화면 anonymous/authenticated 상태에서 정책 안내가 보인다.
- 인증 사용자는 정책 확인 CTA를 누른 경우에만 기관 연결 RPC가 호출된다.
- 기관에 배정되지 않은 기존 문제는 retry availability가 `hard_unavailable`로 처리된다.
- 저장 문제 library RPC는 `is_writing_problem_visible_to_caller`를 사용해 `can_retry`를 결정한다.
