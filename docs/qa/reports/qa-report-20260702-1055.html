아직 검증하지 못한 것

  • pnpm test:e2e가 mobile project 진행 중 timeout되어 tablet/desktop 전체 E2E 완료를 확인하지 못했습니다.
  • 사용자별 데이터 격리와 RLS는 별도 테스트 계정/fixture 없이 직접 검증하지 못했습니다.
  • 피드백/리포트처럼 동적 id가 필요한 화면은 테스트 데이터 문제인지 제품 문제인지 확정하지 못했습니다.
  • local Supabase Docker가 필요한 테스트는 이번 범위에서 별도로 실행하지 않았고, unit suite에서도 skip 상태였습니다.

  • auth-state와 trace zip은 민감 정보 가능성 때문에 보고서 증거 폴더에 복사하지 않았습니다.

개발자용 참고

  • Playwright trace zip은 실패 원인 분석에는 유용하지만, 이번 보고서에는 민감한 세션 정보가 섞일 수 있어 복사하지 않았습니다. 참고: Playwright Trace Viewer, Playwright test use options
  • Supabase service role/secret key는 브라우저에 노출되면 안 됩니다. 이번 QA에서는 정적 번들에 secret 이름이나 값이 들어가지 않았는지 확인했습니다. 참고: Supabase Securing your data
  • Next.js는 NEXT_PUBLIC_ prefix가 붙은 환경 변수를 브라우저 번들에서 사용할 수 있게 만듭니다. secret은 서버 런타임 환경 변수로만 유지해야 합니다. 참고: Next.js Environment Variables, Next.js env config
  • Supabase Data API 접근은 database grants와 RLS 정책 조합으로 결정됩니다. 화면 확인만으로 사용자별 row isolation을 증명할 수 없으므로 별도 RLS 테스트가 필요합니다. 참고: Supabase Securing your API
