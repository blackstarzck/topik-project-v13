1. 한 줄 요약 / Executive summary

판정: 조건부 통과 (P0 0건 · P1 0건). 사용자 화면 34개 라우트가 모두 정상 렌더(하이드레이션 증명)되고 콘솔 에러 0, 접근 제어·시크릿 비노출·admin 경계가 모두 정상입니다. 단, prod 배포 전 반드시 처리할 환경 설정 1건이 있습니다 — NEXT_PUBLIC_SITE_URL 미설정 시 회원가입·비밀번호 재설정·인증 메일 재전송이 전부 멈춥니다(아래 D-1).

비개발자용 한 줄 설명
  • 좋은 점: 화면은 모두 잘 뜨고, 로그인 안 한 사람은 보호 화면에 못 들어가며, 비밀번호 같은 비밀값은 화면 코드에 새어 나오지 않았습니다.
  • 꼭 고칠 것(배포 전): 사이트 주소를 알려주는 설정값 한 개(NEXT_PUBLIC_SITE_URL)가 빠져 있어서, 실제 배포 모드에서 회원가입·비밀번호 재설정·인증메일 재전송 버튼이 "빙글빙글 도는 상태"로 멈춥니다. QA 중에 이 값을 채워 넣자 곧바로 정상 동작했습니다. 배포 환경에도 이 값을 꼭 넣어야 합니다.
  • 여유 있을 때: 잘못된 문제 주소를 직접 입력하면 친절한 빈 화면 대신 일반 오류 화면이 뜨는 경우, 그리고 로그아웃 버튼이 화면 어디에도 안 보이는 점입니다.

이번 QA에서 직접 한 일

  • 자동화 게이트(lint·typecheck·format·build·test) 순차 실행 + prod 빌드 후 e2e(208 테스트 × 3 뷰포트 매트릭스) 실행.
  • 실제 prod 서버(next start)를 띄우고 Playwright로 공개 12 + 보호 22 라우트 전부를 열어 스크린샷·하이드레이션 증명·콘솔 에러를 수집.
  • service role로 E-01/E-02/R-01 피드백·리포트 데이터를 시드 생성해 실제 데이터로 화면 검증 후 정리.
  • 스펙 갭(G1/G5/G6), 접근 제어(ACC-S1/S4/S5), not-found(STATE-S3/S4), 언어 변경(SET-S2), 제출 취소(WRIT-S3) 등을 실제 클릭/입력으로 관찰.
  • e2e 실패 13건을 끝까지 근본 원인 규명 → 12건 환경 설정(NEXT_PUBLIC_SITE_URL) · 1건 테스트 셀렉터 노후화로 분리하고 재검증.

  • 12건 = 환경 설정 갭 NEXT_PUBLIC_SITE_URL 미설정. 인증 흐름의 buildAuthRedirectUrl()이 prod(NODE_ENV=production)에서 이 변수가 없으면 동기 throw → void handleResend() 패턴이라 unhandled rejection → 버튼이 영구 "로딩" 상태로 멈추고 Supabase 호출조차 안 됨. dev에서는 http://127.0.0.1:3000 폴백이 있어 통과 → prod 전용 실패. 이 변수는 .env.example에 필수로 문서화돼 있으나 .env.local엔 누락. QA 중 문서값대로 추가→재빌드하자 요청이 정상 발생(올바른 redirect_to)하고 12 테스트 전부 통과. 네트워크 로그 + 콘솔 에러로 직접 확정.
  • 1건 = 테스트 셀렉터 노후화(제품 결함 아님). core-writing-flow.spec.ts:81이 .ant-modal-title로 D-M1 모달 제목을 찾는데, antd 6에선 제목이 <h2>로 렌더되어 그 클래스가 없음. 실제 모달은 정상 오픈(체크박스·제출 버튼·제목 모두 렌더). 전용 스펙 submission-confirm-modal.spec.ts는 data-testid 셀렉터로 통과.

D-2 · P2 — 인증 redirect 실패 시 무피드백 영구 로딩(코드 견고성)
