## 2. 발견
1. **불일치 0.** 53/54 프롬프트 내장 범위 = constants의 **recommended 범위와 정확히 일치**(200–300, 600–700). 51/52는 빈칸형이라 프롬프트에 글자수 범위가 없음(정상).
2. **hard 하한이 recommended보다 낮은 건 설계 의도** — 53 hard 120(분석 가능 최소) < recommended 200, 54 hard 300 < recommended 600. constants 주석이 명시("analyzable minimum"). 프롬프트는 학습자에게 recommended를 보여주고, 시스템은 hard로 제출 허용(`isCountSubmittable`). **충돌 아님**.
3. (부수) Q54 238건 중 26건이 "(50점)" 점수 리터럴 없음 — 글자수 무관(범위 600~700은 238건 전부 존재). display 카피 편차로 기록만(A3 범위 밖, A2 형태 계약에서 처리 가능).

## 3. 정책 결정 (권고)
- **글자수는 타입별 시스템 상수 유지**(문제별 컬럼 신설 안 함). 프롬프트 내장 범위는 recommended를 보여주는 **표시 카피**이며 상수와 일치해야 함(현재 일치).
- 문제별 글자수 오버라이드 요구가 생기면 그때 **B로 escalate**(현재는 불필요).
