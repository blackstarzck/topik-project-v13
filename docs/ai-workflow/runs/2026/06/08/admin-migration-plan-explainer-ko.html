한 줄 요약

topik-ai를 “옮긴다”는 건 화면 복사가 아니라, v13 데이터베이스에 관리자용 구조를 새로 짓고 이름·상태값을 맞추는 일입니다.

이번 단계에서는 그중 겹치는 부분만, 그것도 실제 작업이 아니라 “설계 문서 3개”만 만듭니다. 코드·데이터베이스·규칙 문서는 지금 건드리지 않습니다.

비유로 이해하기

topik-ai(관리자 앱)는 모델하우스와 같습니다. 방 배치(화면)는 다 보이지만 실제 수도·전기(데이터베이스)는 연결되어 있지 않습니다. 반면 v13(사용자 앱)은 이미 사람이 사는 집이라 수도·전기가 진짜로 들어옵니다.

그래서 “이사”는 가구를 옮기는 게 아니라, 모델하우스의 설계도를 실제 집의 배관 규격에 맞춰 다시 그리는 일입니다. 이번엔 배관을 뜯는 게 아니라 “어디를 어떻게 연결할지 도면만” 그립니다.

지금 상황 — 왜 단순 복사가 안 되나

  • topik-ai에는 진짜 데이터베이스가 없습니다. 화면은 가짜 데이터로 돌고, 데이터 구조는 “이렇게 만들 예정”이라는 문서만 존재(admin-data-contract.md).
  • 진짜 데이터베이스는 v13에만 있습니다. 그래서 v13가 기준이고 topik-ai가 v13에 맞춰야 합니다.
  • 두 앱이 같은 데이터를 다르게 부릅니다. 이름·상태값·역할 체계가 어긋나 있어 “맞추기(정합성)”가 핵심.
  • 기술 스택도 다릅니다. topik-ai = Vite + React 18 + AntD 5, v13 = Next.js 16 + React 19 + AntD 6.
⚠️ 정책 충돌 — 지금 v13 규칙(CLAUDE.md · AGENTS.md · docs/admin-scope-boundary.md)은 “이 저장소는 사용자 화면 전용, 관리자는 나중에 동기화, 관리자용 스키마 추가 금지”입니다. 이 일은 그 경계를 건드리는 결정이라, 이번엔 제안만 만들고 실제 변경은 승인 후에 합니다.

실행 단계 (계획 승인 후 — 전부 문서 작업)

  1. 관련 문서 전부 정독 (topik-ai 스펙 + v13 마이그레이션).
  2. 정합성 정리표 작성 — 겹치는 4개만 채우고, 보류 도메인은 “보류 + 승인 게이트”로 표기.
  3. 통합 설계서 작성 — 인증/역할 매핑안 + 데이터 연결안 + 필드 매핑표 + 단계/게이트.
  4. 경계 갱신 제안문 작성 (적용 안 함, 제안만).
  5. 교차 검수 — 자기 평가는 편향되므로 별도 검수, 한글 카피는 Claude 검수.
