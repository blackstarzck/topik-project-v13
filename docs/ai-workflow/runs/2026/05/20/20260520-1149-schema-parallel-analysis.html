1. 요약 (TL;DR)

  • 두 모델로 병렬 분석: Opus 4.7과 gpt-5.5에 동일 docs를 읽혀 스키마 제안을 독립적으로 받음.
  • gpt-5는 호출 불가: codex CLI가 ChatGPT 계정 인증 모드에서 gpt-5/gpt-5-codex를 정책상 차단. plan 종류 무관. 사용자 결정으로 gpt-5.5(default)로 진행.
  • gpt-5.5는 round-1 → round-2에서 핵심 입장 3개를 뒤집음: draft↔submission 통합 → 분리, library 단순 마크 → polymorphic 별 테이블, organizations/notifications Tier 1 → Tier 2. 같은 모델 1회 호출 결과를 정본으로 받지 말라는 신호.
  • 최종 종합 스키마: Tier 1 MVP에 13개 핵심 테이블, Tier 2 placeholder에 9개. Supabase Postgres + RLS + Storage 고정 baseline 준수.
  • 본 결과는 제안: DDL/마이그레이션은 별도 단계. 사용자 승인 전 production 적용 금지.

2. 분석 방법론

  1. 병렬 dispatch. Opus 4.7 분석 에이전트와 codex CLI(gpt-5.5) 전송 에이전트를 background로 동시 실행.
  2. 동일 docs 베이스. 두 모델 모두 docs/prd.md, docs/spec.md, docs/development/backend-auth.md, docs/development/deferred-scope.md, docs/sitemap.md, docs/ia.md, docs/IA/README.md, docs/flow/user-flow.md, 핵심 15개 docs/IA/<page>/description.md를 읽음.
  3. 3자 비교. Opus 4.7, gpt-5.5 R1, gpt-5.5 R2 결과를 영역별로 비교. 합의는 채택, 불일치는 근거의 강도로 판정.
  4. 종합. 어느 한 모델의 입장을 통째로 채택하지 않고 영역별로 강점을 선택.
  5. Ledger 기록. 모든 decision/위험/follow-up을 context ledger에 추적.

중요 메타 사실

  • codex CLI 응답이 매우 느림 (분 단위, 첫 호출 약 30분). MCP 초기화 + ChatGPT auth 응답 지연.
  • codex의 gpt-5 ping이 명시적으로 "The 'gpt-5' model is not supported when using Codex with a ChatGPT account." 400 응답으로 차단됨. OpenAI API key 인증으로 전환 시에만 gpt-5 가용.
  • PowerShell stdin은 기본 UTF-16 LE 변환 — 한국어 prompt 안전 전달을 위해 cmd.exe /c "chcp 65001 && type ... | codex exec" 패턴으로 우회.

관찰

gpt-5.5의 round-2 변경(분리·polymorphic·Tier 강등) 3개는 모두 "보수적·audit 친화·범위 축소" 방향. prompt를 명시적으로 만들수록 모델이 정통적 정규화 입장으로 이동함. 반대로 AI feedback 정규화에서는 R2가 단순화로 후퇴 — 여기는 R-01 join 요구를 prompt가 명시하지 않은 영향이며, 그래서 Opus의 부분 정규화 결정을 유지함.

5. RLS 핵심 패턴

모든 user-owned 테이블은 alter table ... force row level security로 owner도 우회 못 하게.

5.1 표준 owner check (initplan 최적화)

create policy own_submissions
  on writing_submissions for select to authenticated
  using ( user_id = (select auth.uid()) );

create policy own_submissions_insert
  on writing_submissions for insert to authenticated
  with check ( user_id = (select auth.uid()) );
-- update/delete 정책 없음 → immutable

(select auth.uid())로 감싸면 PostgreSQL이 매 행마다 호출하지 않고 InitPlan으로 1회 평가 — RLS-heavy 테이블 성능에 결정적.

5.2 problems 공개 가시성

create policy published_problems_visible
  on problems for select to authenticated
  using (
    publish_status = 'published'
    and (visibility = 'public' or author_id = (select auth.uid()))
  );

5.3 admin SECURITY DEFINER 함수

create function private.is_admin(uid uuid) returns boolean
  language sql security definer set search_path = public stable
as $$
  select exists(
    select 1 from profiles
    where id = uid and app_role in ('content_admin','platform_admin')
  );
$$;

create policy admins_manage_problems
  on problems for all to authenticated
  using ( private.is_admin((select auth.uid())) )
  with check ( private.is_admin((select auth.uid())) );

5.4 org admin scope (Tier 2 placeholder)

create policy org_admin_scoped_members
  on organization_memberships for select to authenticated
  using (
    user_id = (select auth.uid())
    or exists (
      select 1 from organization_memberships m
      where m.org_id = organization_memberships.org_id
        and m.user_id = (select auth.uid())
        and m.role = 'org_admin'
    )
  );

5.5 draft → submission 승격 트리거 (DDL 단계)

writing_submissions insert 시 같은 (user_id, problem_id)의 활성 draft를 autosave_status = 'superseded'로 마킹. 활성 draft 1개 보장 unique partial index와 함께 작동.
