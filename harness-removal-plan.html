1한 줄 요약

"AI 개발 워크플로우 하네스"는 CI · 로컬 훅 · 빌드 전 검사 · npm 스크립트 · git 커밋 템플릿에 배선되어 있어, 그냥 지우면 빌드·테스트·커밋이 깨집니다. 게다가 보존할 제품 문서·스킬 곳곳이 삭제 대상 파일을 링크/언급합니다(끊어진 참조). 그래서 "배선 끊기 → 테스트 → 스크립트 → 참조정리+문서삭제(같은 커밋) → 전체 검증" 순서로 진행합니다. 스킬·MCP·docs/Wireframe는 절대 건드리지 않습니다.
  • 지우는 것: 규칙/게이트 문서, 작업일지(ledger), 에이전트 패킷, 리뷰·QA 게이트·픽스처, 강제 CI, 로컬 Stop 훅, 강제 스크립트, 생성 산출물(리포트·스크린샷·스모크샷), 그리고 CLAUDE.md·AGENTS.md·README.md의 워크플로우 부분.
  • 남기는 것: 모든 스킬 트리 + skills-lock.json, docs/Wireframe, 제품 소스/설정/문서, 위 파일들의 제품 규칙(admin 경계·데이터 정합성·한국어 커뮤니케이션).
  • 규모: 삭제 추적 파일 약 800개(동시 세션이 스모크샷을 계속 생성해 수치 변동 → 실행 시점 재측정). 참조정리(STRIP) 약 30개 파일.
