이번 협업이 어떻게 굴러갔는지 한눈에

Codex가 먼저 점검한 결과를 Opus가 다시 점검 → 의견 차이를 사용자께서 결정 → 합의 보고서 → 톤 규칙을 영구 규칙으로 고정. 총 8단계로 마무리됐습니다.

색이 누구를 가리키는지

🔵 Codex (GPT 5.5) — 첫 점검자 🟢 Opus 4.7 — 재점검자 🟣 사용자 — 결정권자

흐름 다이어그램

위에서 아래로 시간이 흘러요. 왼쪽 동그라미 색이 그 단계에서 일한 사람(또는 AI)을 가리킵니다.

1 Codex 단독

Codex가 이 프로젝트의 AI 작업 규칙을 점검

7개 항목으로 평가하고, 결함 3건(한글 깨짐 / "아직 코드 없음" 안내 / Node 버전 어긋남)을 지목한 첫 보고서를 만듦.

산출: codex-claude-workflow-evaluation.html
2 사용자 요청

"Opus도 똑같이 점검 → 비교 → 토론 → 합의 → HTML 보고"

Codex 결과를 무조건 받아들이지 말고, 다른 AI가 다시 한 번 검증하고 의견 차이를 토론으로 좁히라는 지시.

3 Opus 단독

Opus가 같은 파일들을 직접 재검증

Codex 발견 4건을 하나씩 다시 확인. 파일 인코딩·내용·자동 점검 모두 직접 실행. Opus 단독 발견 4건도 추가로 도출.

결과: Codex 한 건(한글 깨짐)은 거짓 경보로 판정. 한 건(안내 문구)은 더 심각한 등급으로 격상 제안. 두 건은 그대로 인정. 새 문제 4건(안내문 어긋남 / 문서·코드 자동 비교 부재 / 임시 통과 추적 부재 / 자동 점검 깊이 재평가)을 추가.
4 Opus → 사용자

의견이 갈리는 쟁점 4개만 모아서 사용자에게 질문

전부 묻지 않고 "Codex와 Opus 결론이 다른 부분"만 골라 4개 질문으로 정리. 이건 이 프로젝트의 워크플로에 이미 적혀 있는 "AI 의견이 갈릴 때 사용자에게 올린다" 절차를 그대로 따른 것.

5 사용자 결정

4쟁점에 대해 합의안 확정

한글 깨짐 → 양쪽 결과 모두 적고 재현 권고. 안내 문구 → Opus 의견(가장 급함) 채택. 검토 절차 → Opus 정밀 진단 채택. 문서·코드 자동 비교 부재 → 포함 + "이번 주 안에" 등급.

의미: 두 AI의 평가가 사용자 한 명의 결정으로 합쳐짐. 이게 "합의(consensus)"의 정확한 순간.
6 Opus

합의 결과를 HTML 보고서로 정리 → 사용자 요청 따라 쉬운 톤으로 다시 작성

처음에 전문 용어가 많다는 피드백을 받고, 같은 파일을 "바이브 코더 기준"으로 덮어씀. 신호등 카드 + "무슨 일? / 왜 문제? / 고치는 법?" 3줄 구조 + 끝에 용어집 형식 확립.

산출: opus-vs-codex-workflow-consensus.html (쉬운 톤 버전)
7 사용자 요청

"이 톤을 영구 규칙으로 안내문에 박아라, 어텐션 높게"

일회성이 아니라 앞으로 모든 응답이 같은 톤이 되도록 규칙으로 고정해 달라는 지시.

8 Opus

AGENTS.md + CLAUDE.md에 톤 규칙 추가 → 작업 일지 작성 → 자동 점검 통과

두 안내문에 같은 톤 섹션을 미러링(이전에 합의된 "두 안내문이 다른 말 함" 문제를 더 키우지 않기 위해). 이 프로젝트 규칙상 안내문 변경은 작업 일지가 함께 있어야 자동 점검을 통과하므로 같이 작성.

결과: node scripts/ai-workflow-check.mjs --repo . PASS (= 워크플로 규칙 자동 점검 모두 통과)

이번 세션이 남긴 최종 산출물 3가지

합의 보고서 (쉬운 톤)

두 AI 점검 결과를 합치고, 우선순위로 정리한 한 페이지 보고서

가장 급한 1건 + 곧 고칠 3건 + 여유 있을 때 2건.

이 다이어그램이 보여주는 패턴

"한 AI가 만든 결과를 다른 AI가 다시 본다 → 의견 갈리면 사용자에게 → 결정은 일지로 남긴다"

이 흐름은 이번 세션에서 우연히 일어난 게 아니라, 이 프로젝트의 워크플로 문서 (docs/ai-workflow/review-gates.md의 Disagreement resolution 5단계)에 이미 적혀 있는 절차를 그대로 실행한 것입니다. 그 절차가 실제로 잘 작동한다는 것을 이번 세션이 확인해 줬어요.

핵심: AI를 여러 명 쓴다고 자동으로 품질이 올라가지 않습니다. "다르게 보면 다른 결과 → 사용자가 결정 → 결정 기록" 이라는 절차가 있어야 두 AI의 시너지가 나옵니다.

나오는 단어 풀이

Codex (GPT 5.5)
OpenAI가 만든 AI 도구. 이번 세션에서 첫 점검을 맡았습니다.
Opus (Claude Opus 4.7)
Anthropic이 만든 AI 도구. 이번 세션에서 재점검을 맡았습니다.
합의 (consensus)
두 AI 의견이 다를 때, 사용자 결정으로 하나의 결론으로 모이는 순간. 5단계가 그 지점.
안내문 (AGENTS.md, CLAUDE.md)
AI가 일을 시작하기 전에 가장 먼저 읽는 사용 설명서. AI 두 명이 일관되게 일하도록 잡아주는 핵심 파일.
자동 점검 (workflow checker)
코드/문서를 깃허브에 올릴 때 자동으로 돌아가는 스크립트. "보고서 빠뜨리지 않았나? 일지는 썼나? 검토 받았나?"를 기계로 확인.
작업 일지 (ledger)
이번에 무엇을 / 왜 / 어떻게 바꿨는지 적은 파일. 안내문 같은 핵심 파일을 바꾸면 반드시 함께 만들어야 자동 점검을 통과합니다.
P0 / P1 / P2
고치는 순서. P0 = 지금 당장. P1 = 이번 주 안에. P2 = 여유 있을 때.
바이브 코더
코드를 눈으로는 읽을 수 있지만 전문 개발자는 아닌 독자. 이번 세션부터 모든 응답이 이 독자 기준으로 작성됩니다.
