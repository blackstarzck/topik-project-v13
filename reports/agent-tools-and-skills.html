TALKPIK AI agent handoff

에이전트용 MCP / SKILL 운영 구조

SKILL은 에이전트가 어떤 순서와 기준으로 일할지 정하는 절차서이고, MCP는 공식 문서, DB, 브라우저, 배포 환경처럼 실제 외부 상태를 조회하거나 실행하는 도구 연결부입니다. TALKPIK에서는 프로젝트 로컬 SKILL이 작업 계약을 통제하고, MCP는 그 계약 안에서 필요한 검증과 조회를 수행합니다.

운영 원칙

최종 실행 계약은 프로젝트에 커밋되는 .codex/skills/talkpik-* 스킬과 docs/ai-workflow/ 문서에 둡니다. 글로벌로 설치된 Vercel, Supabase, React best-practice 스킬은 있으면 참고하지만, 다른 사람이 이어받을 때 반드시 존재한다고 가정하지 않습니다.

1. 분류 요청을 읽고 docs/spec.md 기준으로 UI, Supabase, AI, 배포, 품질 검증 중 어디에 속하는지 분류합니다.
2. 로컬 SKILL 선택 talkpik-orchestrator가 작업에 맞는 하위 SKILL을 선택합니다.
3. MCP 조회 Context7, Supabase, Vercel, Browser, GitHub, Bright Data MCP를 필요한 경우에만 호출합니다.
4. 검증 테스트, 타입체크, 빌드, 브라우저 QA, RLS, 배포 로그 등으로 완료 근거를 남깁니다.

프로젝트 로컬 SKILL

SKILL

talkpik-orchestrator

모든 개발 작업의 입구입니다. 에이전트가 요청을 받으면 docs/spec.md, docs/agent-index.md, 관련 docs/development/*.md를 읽고 작업 유형을 분류합니다.

구현은 .codex/skills/talkpik-orchestrator/SKILL.md에 두고, 어떤 요청이면 어떤 하위 SKILL을 호출하는지, 필수 문서, 중단 조건, 최종 보고 형식만 짧게 정의합니다.

SKILL

talkpik-next-bootstrap

Next.js App Router 프로젝트 초기화와 기본 구조 생성을 담당합니다. pnpm, src/app, src/components, src/lib, src/theme, src/stores, src/styles 구조를 spec.md에 맞춥니다.

구현 시 Next.js 공식 문서와 Context7 MCP를 조회하게 하고, vercel:nextjs가 있으면 참고하되 shadcn 전제는 금지합니다.

SKILL

talkpik-ui-system

Ant Design과 Tailwind를 하나의 디자인 시스템으로 쓰게 만드는 규칙입니다. AntD ConfigProvider, theme token, component token, src/theme/tailwind-bridge.ts, --app-* CSS 변수 연결을 강제합니다.

구현은 docs/ant-design/08-theme-architecture.md를 필수로 읽게 하고, Tailwind가 독립 팔레트 없이 AntD token에서 파생된 CSS 변수만 쓰는지 검사합니다.

SKILL

talkpik-state-data

상태 관리 기준을 고정합니다. Server Components, server actions, React local state, URL search params, React Hook Form, TanStack Query, Zustand의 역할을 분리합니다.

구현은 docs/spec.md의 State Management Model과 docs/development/stack.md를 필수 입력으로 삼고, store, query, form, schema 위치가 맞는지 체크리스트로 검증합니다.

SKILL

talkpik-supabase-boundary

Supabase Auth, Postgres, RLS, Storage, SSR client, env var 보안을 다룹니다. 프로젝트 로컬 SKILL이 최종 권위이고, Supabase 공식 Agent Skills와 Supabase MCP는 upstream reference로 둡니다.

핵심 규칙은 service_role 브라우저 노출 금지, exposed table RLS 필수, migration/advisor 검증, auth claim 사용 기준, server/client Supabase client 분리입니다.

SKILL

talkpik-quality-gate

완료 전 검증 순서를 통제합니다. 테스트, lint, typecheck, build, Playwright/browser QA, Supabase RLS 검증, Vercel preview 검증을 작업 유형별로 실행하게 합니다.

구현은 docs/ai-development-workflow.md와 docs/ai-workflow/report-template.md를 기반으로 하며, 코드 변경이면 TDD 예외 여부를 기록하고 UI 변경이면 browser/visual QA를 요구합니다.

에이전트가 사용할 MCP 도구

MCP

Context7 MCP

최신 공식 문서를 조회하는 도구입니다. Next.js, Tailwind, AntD, Supabase, TanStack Query처럼 빠르게 변하는 라이브러리는 에이전트 기억에 의존하지 않고 Context7로 확인합니다.

구현은 각 SKILL에 “외부 API나 라이브러리 사용 전 Context7로 공식 문서 확인” 규칙을 넣고, 결과가 부족하면 웹 검색으로 fallback하게 합니다.

MCP

Supabase MCP

실제 Supabase 프로젝트 상태를 조회하고 SQL, advisors, schema, RLS 상태를 확인하는 도구입니다. DB 작업에서는 read-only 우선, migration 전 SQL 검증, advisors 실행, RLS 확인을 기본 게이트로 둡니다.

쓰기 권한이 필요한 경우 작업 범위와 위험을 기록하고, service_role을 브라우저에 노출하지 않는지 반드시 검사합니다.

MCP

Vercel MCP 또는 Vercel CLI

배포, env var, preview, logs, build 설정을 확인하는 도구입니다. talkpik-quality-gate에서 사용합니다.

구현은 preview URL 공유 전 env var 구성 확인, build 성공, runtime logs 확인, rollback 가능성 확인을 게이트로 둡니다.

MCP

Browser / Playwright MCP

실제 화면을 열어 UI가 작동하는지 확인하는 도구입니다. UI나 user flow 변경 후 dev server를 띄우고, 주요 route, console/network error, responsive layout, text overflow, loading/error/empty state를 확인합니다.

TALKPIK은 학습 앱이므로 “화면이 뜬다”가 아니라 “사용자가 다음 학습 행동을 할 수 있다”까지 확인해야 합니다.

MCP

GitHub MCP

PR, issue, CI 기반 협업에 쓰는 도구입니다. 로컬 개발 단계에서는 필수로 두지 않고, PR 생성, CI 실패 분석, 리뷰 코멘트 반영이 필요할 때만 사용합니다.

GitHub MCP가 없을 경우 git diff, 로컬 테스트, 수동 보고로 대체하는 fallback을 로컬 SKILL에 둡니다.

MCP

Bright Data MCP

웹과 커뮤니티 조사를 위한 보조 도구입니다. 스택 의사결정, 경쟁 패턴, 커뮤니티 리스크 조사, 문서 업데이트 근거 수집 같은 research 작업에서 사용합니다.

제품 코드 구현의 직접 근거는 공식 문서와 프로젝트 docs가 우선이고, Bright Data 결과는 보조 근거로 기록합니다.

금지해야 할 지름길

글로벌 SKILL 또는 커뮤니티 SKILL이 설치되어 있더라도 TALKPIK의 로컬 문서와 충돌하면 사용하지 않습니다. 특히 shadcn 도입, 독립 Tailwind palette, browser-visible secret, RLS 없는 exposed table은 금지합니다.
