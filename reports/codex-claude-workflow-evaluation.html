항목 판정 근거 평가

자동 workflow checker 통과 scripts/ai-workflow-check.mjs, .github/workflows/ai-workflow-check.yml PR body, commit trailer, ledger, plan 구조 일부가 자동 검사된다.
Cross-model review 부분 통과 docs/ai-workflow/review-gates.md, ledger의 Cross-model review: 필드 요구사항은 강하지만 실제 독립 reviewer 여부는 텍스트 기록에 의존한다.
Claude Code 지침 가독성 결함 CLAUDE.md의 한국어 문단 mojibake Claude가 핵심 상태와 source-of-truth 설명을 잘못 해석할 가능성이 있다.
프로젝트 상태 문구 불일치 AGENTS.md, CLAUDE.md는 pre-implementation이라고 하나 src/, package.json이 존재 “docs가 유일한 현재 소스”라는 운영 전제가 약해졌다. 현재 코드를 docs와 함께 reconcile해야 한다.
Node 기준 불일치 package.json은 Node >=24 <25, GitHub Actions workflow는 Node 22 현재 checker는 통과할 수 있지만, 저장소 표준 런타임과 CI workflow evidence job 기준이 다르다.

우선순위별 개선 권고

P1. CLAUDE.md 인코딩 깨짐 복구

Claude Code가 직접 읽는 프로젝트 지침에 mojibake가 있어, source-of-truth와 프로젝트 상태 설명이 불명확하다. 같은 내용이 AGENTS.md에 더 깨끗하게 있으므로 이를 기준으로 복원하는 것이 안전하다.

P1. pre-implementation 문구 갱신

현재 저장소에는 src/, package.json, 테스트/Next 설정이 존재한다. 지침은 “production source exists after...” 상황으로 전환되어야 하며, 구현 전에는 docs와 current source를 함께 대조하도록 표현해야 한다.

P2. CI Node 버전 정렬

package.json의 engines와 ai-workflow-check.yml의 Node 버전이 다르다. workflow checker만 실행하더라도 팀의 기준 런타임과 불일치하면 향후 검증 확장 시 혼선을 만든다.

P2. 독립 reviewer 증거 강화

현재 checker는 Cross-model review: 필드 존재를 본다. 실제 Claude/Codex reviewer 결과 링크나 packet 위치를 ledger에 요구하면 형식적 통과 가능성을 줄일 수 있다.
