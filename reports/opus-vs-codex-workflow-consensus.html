두 안내문이 살짝 어긋나 있고, AI 자동 점검 도구가 "문서와 실제 코드가 같은지"는 아직 안 보고 있어요.

이 프로젝트가 어떻게 일하는지 (3줄 요약)

아래는 평가 결과를 이해하기 위해 알아두면 좋은 배경입니다.

배경 이 프로젝트의 일하는 방식

한 줄로: 사람 한 명 + AI 두 명(Codex와 Claude)이 같은 코드 위에서 함께 일합니다.

규칙의 핵심: AI가 어떤 작업이든 시작하기 전에 정해진 문서 몇 개를 먼저 읽고, 작업 일지를 남기고, 한 AI가 만든 결과를 다른 AI가 검토하도록 강제합니다.

자동 장치: 위 규칙을 지켰는지 매번 점검하는 스크립트가 있고, 깃허브에 PR(코드 제출)할 때 자동으로 돌아갑니다.

지금 바로 고쳐야 할 것

"이걸 안 고치면 다음 작업도 같은 함정을 밟습니다"에 해당하는 단 한 가지입니다.

P0 · 가장 급함 안내문이 "아직 코드 안 짰음"이라고 잘못 적혀 있어요

무슨 일? 모든 AI가 작업 시작 전에 먼저 읽는 두 파일(AGENTS.md, CLAUDE.md)에 "이 저장소는 아직 코드가 없는 상태"라고 적혀 있습니다.

왜 문제? 실제로는 코드가 이미 많이 쌓였습니다. 4단계, 5단계 작업은 이미 끝났고 6단계 작업이 진행 중이에요. 그런데도 AI는 "코드가 없다"고 가정한 채 일을 시작하니, "문서만 보면 된다"고 잘못 판단하기 쉽습니다.

고치는 법: 두 파일의 해당 문장을 "코드가 이미 있음. 작업 전에 문서와 실제 코드를 함께 확인할 것"으로 바꾸기. 5분이면 끝나는 수정인데 영향력은 가장 큽니다.

곧 고쳐야 할 것 (이번 주 안에)

P1 두 안내문이 서로 다른 말을 하고 있어요

무슨 일? AGENTS.md(Codex가 주로 읽음)에는 최근 "AI가 사용자 말에 무조건 동의하지 말 것"이라는 중요한 규칙이 추가됐는데, CLAUDE.md(Claude가 주로 읽음)에는 빠져 있어요.

왜 문제? Claude는 더 약한 규칙을 가진 채 일하게 됩니다. 두 AI가 다른 기준으로 행동하면 검토 품질이 어긋나요.

고치는 법: CLAUDE.md에도 같은 내용을 복사해 넣거나, "AGENTS.md를 그대로 따른다"는 한 줄로 줄이기. 위 P0와 같은 작업에서 함께 정리하면 좋습니다.

P1 "문서에 적힌 화면 = 실제 만든 화면"인지 자동 점검이 없어요

무슨 일? 현재 자동 점검 도구는 "보고서 형식이 맞는지"는 보지만, "문서에 적힌 페이지 목록이 실제 코드에 다 있는지"는 보지 않습니다.

왜 문제? 코드가 쌓일수록 문서와 실제 화면이 조용히 어긋날 수 있습니다. 사람이 매번 눈으로 확인해야 한다면 곧 놓치게 돼요. 지금이 가장 정리하기 쉬운 시점입니다.

고치는 법: "문서에 적힌 페이지 주소 목록"과 "실제 코드에 만들어진 페이지 목록"을 비교하는 간단한 스크립트를 추가하기.

P1 위 P0 같은 실수가 다시 안 생기게 자동 점검에 추가

무슨 일? "코드 안 짰음"이라고 적혀 있으면서 동시에 코드 폴더(src/)가 존재하면 자동으로 경고를 띄우는 규칙을 추가합니다.

왜 문제? 이번에 발견된 결함을 사람이 매번 신경 쓸 필요가 없게, 도구가 대신 잡아주도록 만드는 거예요.

고치는 법: 자동 점검 스크립트에 한 줄짜리 검사를 추가.

여유 있을 때 (다음 달쯤)

P2 Node 버전 숫자가 두 곳에서 달라요

코드 설정 파일은 "Node 24"를, 깃허브 자동 점검은 "Node 22"를 씁니다. 지금은 둘 다 잘 돌아가지만 헷갈리는 원인이 됩니다. 한쪽으로 맞추기.

P2 "AI 한 명만 있어서 검토 못 받음" 비율 추적

규칙상 "다른 AI가 검토 불가하면 사유 적고 통과"가 허용됩니다. 안전장치예요. 하지만 이 예외가 얼마나 자주 쓰이는지 아무도 안 보고 있어서, 매번 예외로 통과해도 모릅니다. 한 달에 한 번 비율만 집계하는 간단한 보고가 있으면 좋아요.

두 AI가 다르게 본 부분 (그리고 어떻게 합의했는지)

Codex가 먼저 만든 보고서와 Claude(Opus 4.7)의 재점검 결과가 다른 4개 항목입니다. 사용자께서 직접 판정을 내려 합의했습니다.

Codex 의견
"한글이 깨져 보임 — 결함이다"

한국어 안내문이 깨져 보여서 AI가 잘못 해석할 수 있다고 봤어요.

Claude 의견
"파일은 멀쩡함 — 거짓 경보"

파일을 직접 열어 확인했더니 한글이 정상이에요. Codex 쪽 화면 표시 문제로 보입니다.

합의: 양쪽 결과를 모두 적고, Codex 환경에서 한 번 더 열어 재현되는지 확인 권고. 파일 자체는 손댈 필요 없음.
Codex 의견
"안내문 잘못된 거 — 중요(P1)"
Claude 의견
"가장 급함(P0) — 모든 작업 시작에 영향"

모든 AI 세션이 이 문장을 가장 먼저 읽기 때문에, 한 곳을 잘못 적으면 모든 작업이 잘못된 가정으로 시작합니다.

합의: Claude 의견(P0) 채택. 위쪽 "지금 바로 고쳐야 할 것"에 단독으로 올림.
Codex 의견
"검토 강제력이 약하다"

"검토받았다"고 글로 적으면 통과되니까 형식적이라고 봤어요.

Claude 의견
"구조는 튼튼함. 진짜 약점은 다른 곳"

실제로는 검토 절차가 꽤 촘촘해요. 진짜 문제는 "검토 못 받았다고 임시 통과한 경우가 얼마나 많은지" 아무도 안 본다는 것.

합의: Claude의 더 정확한 진단 채택. 위 P2 항목으로 "임시 통과 비율 추적" 권고.
Codex 의견
언급 없음
Claude 의견
"문서랑 코드가 같은 말 하는지 자동 검사가 없음"

새로 발견한 항목. 코드가 쌓이는 지금이 가장 큰 위험.

합의: 포함. 위 P1 항목으로 올림.

AI 두 명 (Codex / Claude)
이 프로젝트는 두 종류 AI를 같이 씁니다. 서로 다른 회사가 만든 도구라 강점이 달라요. 한 AI가 짠 코드를 다른 AI가 검토하면 실수를 잘 잡아냅니다.
안내문 (AGENTS.md, CLAUDE.md)
AI에게 "여기서는 이렇게 일해라"라고 알려주는 사용 설명서입니다. AI는 매번 이 파일부터 읽고 일을 시작해요.
자동 점검 도구
코드를 깃허브에 올리면 자동으로 돌아가는 스크립트입니다. "보고서를 빠뜨리지 않았나? 검토는 받았나? 일지는 썼나?"를 기계적으로 확인해요.
작업 일지
AI가 어떤 작업을 했는지, 무슨 문서를 봤는지, 어떤 결정을 했는지를 기록한 파일입니다. 다음에 다른 AI가 작업을 이어받을 때 길잡이가 됩니다.
임시 통과 (degraded mode)
"원래는 다른 AI가 검토해야 하는데 지금 불가능하다, 사유는 ○○이다"라고 적으면 일단 넘어가는 규칙. 안전장치지만 자주 쓰면 검토 품질이 떨어져요.
P0 / P1 / P2
고치는 순서. P0는 지금 당장, P1은 이번 주 안에, P2는 여유 있을 때.
Phase 4 / 5 / 6
이 프로젝트의 작업 단계입니다. 큰 기능을 단계별로 잘라서 하나씩 완성하고 있어요. 지금 6단계가 진행 중이에요.
