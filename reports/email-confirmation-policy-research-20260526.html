a) 미인증 사용자 정리 함수

-- supabase/migrations/2026XXXXxxxxxx_cleanup_unconfirmed_users.sql
-- =====================================================================
-- TALKPIK AI · Phase 7+ · Unconfirmed user retention policy
-- Default 30d. 04:00 UTC / 13:00 KST daily.
-- =====================================================================

create or replace function private.cleanup_unconfirmed_users(
  retention_days int default 30,
  dry_run boolean default false,
  max_batch int default 1000
)
returns int
language plpgsql security definer
set search_path = pg_catalog, public, auth, storage
as $$
declare
  victim_ids uuid[];
  deleted_count int;
begin
  if retention_days < 1 then
    raise exception 'retention_days must be >= 1 (got %)', retention_days;
  end if;
  if max_batch < 1 then
    raise exception 'max_batch must be >= 1 (got %)', max_batch;
  end if;

  select array_agg(id) into victim_ids
  from (
    select id from auth.users
    where email_confirmed_at is null
      and created_at < now() - make_interval(days => retention_days)
      and is_sso_user = false
    order by created_at
    limit max_batch
  ) sub;

  deleted_count := coalesce(array_length(victim_ids, 1), 0);

  if dry_run then
    raise log 'cleanup_unconfirmed_users dry_run: would delete % users older than % days',
      deleted_count, retention_days;
    return deleted_count;
  end if;

  if deleted_count > 0 then
    -- Storage objects 먼저 정리 (Auth user 삭제 충돌 방지 — Codex Round 2 NF3)
    delete from storage.objects where owner = any(victim_ids);

    -- public.profiles는 FK ON DELETE CASCADE로 자동 정리 (검증된 invariant)
    delete from auth.users where id = any(victim_ids);

    raise log 'cleanup_unconfirmed_users: deleted % users older than % days',
      deleted_count, retention_days;
  end if;

  return deleted_count;
end;
$$;

revoke all on function private.cleanup_unconfirmed_users(int, boolean, int)
  from public, anon, authenticated;

comment on function private.cleanup_unconfirmed_users(int, boolean, int) is
  'Delete unconfirmed auth.users older than N days (default 30) and their owned storage objects. '
  'SECURITY DEFINER with locked search_path. dry_run=true returns count without deleting. '
  'max_batch caps deletes per call. profiles row removed via FK ON DELETE CASCADE.';

b) pg_cron 스케줄 (idempotent)

select cron.unschedule('cleanup-unconfirmed-users')

select cron.schedule(

A-2. /auth/callback 분기 contract

// Route Handler 핵심 로직 (의사 코드)
export const dynamic = 'force-dynamic';

export async function GET(req) {
  const url = new URL(req.url);
  const next = sanitizeNext(url.searchParams.get('next')); // relative-only, 기본 /dashboard

  const token_hash = url.searchParams.get('token_hash');
  const type      = url.searchParams.get('type');
  const code      = url.searchParams.get('code');

  try {
    if (token_hash && type) {
      // type: 'signup' | 'recovery' | 'email_change' | 'email' (PKCE 매직링크)
      await supabase.auth.verifyOtp({ token_hash, type });
    } else if (code) {
      await supabase.auth.exchangeCodeForSession(code);
    } else {
      return redirect('/auth/error?reason=unknown');
    }
    return redirect(next);
  } catch (err) {
    console.error('[auth/callback]', err); // raw error_description은 서버 로그에만
    const reason = mapSupabaseErrorCode(err.code) ?? 'unknown';
    const retry  = err.headers?.get?.('retry-after');
    const qs     = retry ? `&retry_after_seconds=${retry}` : '';
    return redirect(`/auth/error?reason=${reason}${qs}`);
  }
}

bad_code_verifier Supabase "보안 검증에 실패했어요. 같은 브라우저에서 끝까지 진행해주세요." 처음부터 다시
user_not_found Supabase "이 계정은 더 이상 존재하지 않아요. 다시 가입하시면 됩니다." (cleanup-deleted user 경로) 다시 가입하기
over_email_send_rate_limit Supabase "메일을 너무 많이 보냈어요. 잠시 후 다시 시도해주세요." (Retry-After 분 표시) Retry-After countdown 후 자동 활성
over_request_rate_limit Supabase "요청이 너무 많아요. 잠시 기다려주세요." Retry-After countdown 후 자동 활성
email_not_confirmed Supabase "이메일 인증이 아직 완료되지 않았어요. 받은편지함을 확인해주세요." 인증 메일 재전송
signup_disabled Supabase "현재 신규 가입이 일시 중단됐어요. 잠시 후 다시 시도해주세요." 홈으로
access_denied OAuth fragment (현 phase 외) "인증이 거부됐어요." 다시 시도 — OAuth 도입 시 활성
unknown catchall "처리 중 문제가 생겼어요. 잠시 후 다시 시도해주세요." 홈으로

A-4. Supabase 자체 rate-limit (앱은 추가 limiter 안 둠)

D2 합의: MVP는 Supabase 한도에 의존. 한도 도달 시 위 매핑 표에서 우아하게 안내.

정보Supabase 인증 한도 (2026-05 기준)

  • OTP / Magic link (/auth/v1/otp): 같은 사용자에게 60초 이내 재요청 불가, 프로젝트 전체 시간당 30회.
  • Email send (signup confirm / recover / email change) — built-in SMTP: 시간당 2회. 커스텀 SMTP면 더 높음.
  • 일반 endpoint: over_request_rate_limit 트리거 가능 (수치 endpoint별 가변).
  • 출처: Supabase Auth Rate Limits

A-5. 다른 서비스는 어떻게 처리하나

서비스 / 가이드 에러 페이지 패턴 Resend cooldown
Supabase 공식 example Route Handler /auth/callback → 실패 시 단일 에러 페이지 redirect OTP 60s 강제, 시간당 30회 cap
Keycloak 실패 시 친근한 에러 페이지 30초 cooldown 기본, 3회 초과 시 1시간 차단

A-6. UX 제약 (Codex Round 1~2에서 강화된 규칙)

  • α
    사용자를 에러에 가두지 않기
    모든 reason에는 최소 1개 primary CTA + (가능하면) secondary 제공. "다시 시도" / "로그인" / "가입" 중 하나는 반드시 노출.
  • β
    Email prefill은 untrusted
    ?email= query는 가시 + 편집 가능한 input의 초기값으로만 사용. 절대 자동 resend X. URL 변조로 다른 사람 이메일에 메일 발송 방지.
  • γ
    raw error_description은 서버 로그에만
    URL 파라미터로 노출 X. Supabase가 보낸 영어 에러 원문을 사용자에게 보여주지 않음. 위 매핑 표 한국어 문구만 표시.
  • δ
    next open redirect 차단
    ?next= query는 /로 시작 + // 없음 + scheme 없음만 허용. 그 외엔 /dashboard로 fallback.
  • ε
    Resend 항상 보이는 email input 요구
    버튼 한 번에 fire-and-forget 안 함. 사용자가 자기 이메일을 한 번 더 확인 후 제출. 오·남용 방지.

용어집

auth.users
Supabase가 관리하는 로그인 정보 테이블. 이메일·비밀번호·세션 토큰 같은 인증 데이터가 들어있음. 우리는 직접 안 건드림.
public.profiles
우리 앱이 정의한 사용자 프로필 테이블. 표시 이름·역할·플랜·소개 같은 운영 데이터. auth.users와 같은 id(uuid)로 1:1 연결.
email_confirmed_at
사용자가 인증 메일을 클릭한 시점. NULL이면 아직 미인증. 우리 트리거는 이 값과 무관하게 가입 즉시 profile을 만듦.
선점 공격 (Pre-account takeover)
공격자가 피해자 이메일을 미리 차지해두고 피해자가 나중에 가입할 때 비밀번호 충돌·세션 탈취를 노리는 수법. 미인증 계정이 오래 살아있을 때 가능.
pg_cron
PostgreSQL용 cron 확장. 데이터베이스 안에서 직접 스케줄링 가능. Supabase 대시보드에서 확장 활성화 후 사용.
SECURITY DEFINER
해당 함수를 정의한 사용자(보통 postgres)의 권한으로 실행되는 함수. 일반 사용자도 호출하면 강한 권한으로 동작. search_path 잠금 필수.
FK ON DELETE CASCADE
부모 테이블 행이 삭제될 때 자식 테이블 행도 같이 삭제되는 외래 키 옵션. 본 보고서 검증 시점에 public.profiles → auth.users는 이미 CASCADE 적용 상태.
retention period (보관 기간)
미인증 상태로 살아남을 수 있는 최대 일수. 산업 표준이 아니라 우리 학습 서비스 UX 선택. 권장 30일.
private schema
Supabase가 만든 비공개 schema. public과 달리 API 노출되지 않음. SECURITY DEFINER 함수의 적절한 거주지.
dry_run / max_batch
안전장치. dry_run=true는 삭제 후보 건수만 반환. max_batch는 한 번에 삭제 최대치 (default 1000) — 잘못된 retention 인자가 들어와도 광범위 삭제 방지.
