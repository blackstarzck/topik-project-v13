self-test 깨짐, CI가 self-test 안 돌림, 지금 브랜치에서 체커 자체가 FAIL. "자기 검사 통과 못 하는 상태".

먼저 비유로 이해하기

비유 1 · 운전면허 시험

이 워크플로 = 운전면허 시험장.

시험 문제집(=문서 4종)은 잘 만들어졌고, 채점 기계(=체커 스크립트)도 있어요. 근데 채점 기계가 고장 났는데 아무도 모름(self-test FAIL). 더 위 시험 감독관(=CI)은 "채점 기계가 멀쩡한가?"는 안 보고 "이 응시자가 통과했나?"만 봐요. 결과: 응시자는 합격 도장 받고 도로로 나갑니다.

비유 2 · 자물쇠 가게

이 워크플로 = 자물쇠 잘 만든 가게.

설계자(=문서)는 "이 자물쇠는 7가지 방식으로 시험을 통과해야 합니다"라고 적어놨어요. 근데 시험 기계(=체커)는 그 중 5가지만 검사하고, 자물쇠 자체에 들어가는 부품 하나(="Untouched relevant docs" 필드)는 시험에 빠져 있어요. 가게 주인은 "다 통과했다"고 말하지만 실제로는 안 봤어요.

워크플로가 작동하는 구조 (눈으로 보기)

문서가 말하는 흐름은 단순한데, 실제로 어디서 끊어졌는지 색깔로 표시했어요. 빨강 = 깨진 곳, 노랑 = 어긋난 곳, 초록 = 잘 작동.

초록 = 잘 됨, 노랑 = 어긋남, 빨강 = 깨짐 · 화살표 점선 = "원래는 연결되어야 하는데 안 됨"

지금 당장 (P0) — "자기 검사를 통과 못 함"

P0-1 체커의 self-test가 깨진 채 방치돼 있어요

무슨 일? node scripts/ai-workflow-check.selftest.mjs 돌리면 line 429에서 AssertionError로 죽어요.

왜 문제? 체커에 "Light Spec 안에 Audience: 필드가 있어야 한다"는 검사가 추가됐는데(ai-workflow-check.mjs:391-399), self-test의 가짜 데이터에는 그 필드가 없어요. 검사 규칙은 업그레이드됐는데 시험문제는 그대로. 결과적으로 체커 자체에 새로운 버그가 들어가도 잡을 그물이 없는 상태예요.

고치는 법: self-test의 fixture에 Audience: user 한 줄 추가. 5분 작업.

AssertionError [ERR_ASSERTION]: false !== true at testLightSpecPresenceCheckedForPhaseLedgers at scripts/ai-workflow-check.selftest.mjs:429

P0-2 CI가 self-test와 fixture 테스트를 안 돌려요

무슨 일? .github/workflows/ai-workflow-check.yml은 ai-workflow-check.mjs만 실행해요. 별도로 존재하는 self-test, UX/UI fixture, QA Gate fixture 3개 검증 스크립트는 무시.

왜 문제? 비유로 말하면, 시험 감독관(=CI)이 "응시자가 통과했나?"는 보지만 "채점 기계 자체가 멀쩡한가?"는 안 봐요. P0-1 같은 회귀가 들어가도 CI를 그냥 통과합니다. 안전망에 구멍이 뚫린 채 사용 중.

고치는 법: CI yaml에 세 줄 추가 — node scripts/ai-workflow-check.selftest.mjs, node scripts/test-uxui-fixtures.mjs, node scripts/test-qa-gate-fixtures.mjs.

P0-3 지금 이 브랜치에서 체커가 FAIL 상태예요

무슨 일? node scripts/ai-workflow-check.mjs --repo . 돌리면 "implementation/config workflow changes require a run ledger" 오류로 FAIL.

왜 문제? Untracked 파일 docs/ai-workflow/runs/2026/05/26/20260526-auth-error-callback-ux-review.md의 파일명이 규칙(YYYYMMDD-HHMM-slug.md)을 어겨요 — 시간(-HHMM-) 부분이 빠짐. 그래서 체커는 "이건 ledger 아님 → ledger 필요한데 없음 → FAIL". 이미 룰을 어긴 파일이 들어가 있는 증거.

고치는 법: 파일명을 20260526-1430-auth-error-callback-ux-review.md처럼 시간 박아서 리네임. 또는 ledger 형식 아니면 다른 위치로 옮기기.

이번 주 안 (P1) — 문서랑 체커가 어긋남

"문서는 요구하는데 자동 검사가 못 잡거나, 자동 검사가 너무 헐거워서 엉뚱한 걸 잡는" 사례들이에요.

항목 문서가 요구하는 것 체커가 실제 하는 일 상태
P1-1
UI 변경 감지		 UI 패턴이 바뀌면 UX/UI Consistency Pass + QA Gate 강제 regex /theme/i가 경로 어디든 "theme" 글자 있으면 매치 → docs-only 변경도 UI 게이트 발동 너무 헐거움
P1-2
Untouched relevant docs		 entry doc + agent-index + report template 모두 필수 evidence로 명시 ledger 필수 섹션 3개에 포함 안 됨 → 자동 검사 0% 강제 안 됨
P1-3
QA Gate failed 사유		 "failed: 막힌 원인 명시" 의무 bare skipped만 검사, bare failed는 PASS 강제 안 됨
P1-4
로컬 vs CI 체커 입력		 (특별한 언급 없음) 로컬: git status · CI: git diff base..head → 다른 결과 가능 불일치
P1-5
Task table의 Audience 컬럼		 phase Audience가 both면 컬럼 필수 Subagent-eligible 컬럼만 검사, Audience 컬럼은 무시 강제 안 됨

대표 사례 P1-1: UI 감지 regex가 docs까지 잡는 함정

무슨 일? UI_CHANGE_PATTERNS에 /theme/i가 있어요. 경로 아무 데나 "theme" 글자만 들어가면 매치.

왜 문제? docs/ant-design/08-theme-architecture.md 같은 docs-only 변경에도 UX/UI Consistency Pass + QA Gate를 요구해요. 작업과 무관한 게이트가 발동되면 AI는 "이 게이트는 무시해도 돼"라고 학습하기 시작합니다. 게이트 자체의 신뢰도가 떨어지는 길.

고치는 법: /theme/i → /^src\/theme\// 또는 /\/theme[\/-]/i로 경로 경계 명시.

    AGENTS.md/CLAUDE.md의 비협상 룰이지만 본질적으로 인간 검토 의존. 사고 경험("응답이 영어로 나옴")이 쌓이면 별도 검사 필요.
  • 5
    잘못된 형식 ledger가 이미 1개 들어가 있음 (P0-3과 연관)
    20260526-auth-error-callback-ux-review.md가 시간 부분 빠진 채 저장됨. 워크플로의 강제력이 한 번 뚫린 증거. 향후 더 들어오기 전에 정리 필요.

용어집

체커
scripts/ai-workflow-check.mjs. AI가 워크플로 룰을 어겼는지 자동 검사하는 Node.js 스크립트.
self-test
체커 자체가 멀쩡한지 검사하는 별도 테스트. 채점 기계의 채점 기계.
CI
Continuous Integration. PR 올라오면 GitHub가 자동으로 돌리는 검사. .github/workflows/에 정의.
ledger
작업 일지. docs/ai-workflow/runs/YYYY/MM/DD/YYYYMMDD-HHMM-slug.md 형식.
Light Spec
phase 단위 작업의 1쪽짜리 간단 명세. docs/ai-workflow/light-specs/phase-N-...md.
Audience
UI/권한 분기에서 그 작업이 user 화면용인지 admin 화면용인지 둘 다(both)인지.
UX/UI Consistency Pass
UI 변경 작업 끝나기 전에 Tokens/Components/A11y/Responsive 4가지 검사 통과 의무.
QA Gate
로컬 앱 부팅 + user path 직접 클릭 + 콘솔 에러 캡처. UI 작업의 마지막 안전망.
degraded
정상 검증 못 했지만 사유 적고 통과시킨 상태. "임시 통과" 라벨이지 합격은 아님.
fail-closed
의심스러우면 멈춤. 통과 안 시킴. 문 닫고 사람 부르는 모드.
Architecture Pass
phase 끝낼 때 "코드 구조가 도메인 경계와 맞는지" 마지막 점검.
Cross-model review
다른 AI에게 검토받기. Codex가 짠 코드는 Claude가, Claude가 짠 건 Codex가 검토.
fixture
테스트용 가짜 데이터. 시험문제의 정답지 역할.
