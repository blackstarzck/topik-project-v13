비개발자용 설명서 · IA 구현 검수

34개 화면이 “진짜 쓸 수 있는 상태인지” 확인하는 절차입니다

이 문서는 TALKPIK AI의 화면, 팝업, 인증 처리 경로를 문서와 실제 구현 기준으로 점검하는 방법을 쉽게 풀어쓴 설명서입니다.

한 줄 결론

단순히 “페이지가 열리는가?”를 보는 절차가 아닙니다. 사용자가 길을 잃지 않는지, 버튼이 맞는지, 뒤로가기가 안전한지, 모바일에서 깨지지 않는지, 정책을 과장하지 않는지까지 봅니다. 이제는 그 판단을 말로만 남기지 않고, 스크립트가 읽을 수 있는 증거로 남깁니다.

비유하면 건물 완공 검사입니다

문이 열리는지만 보면 부족합니다. 안내판, 비상구, 조명, 동선, 직원 전용 구역까지 봐야 “사용 가능”이라고 말할 수 있습니다.

이번 변경의 핵심

이번 변경은 Phase 5만 바꾸는 일이 아닙니다. 전체 절차를 “스크립트가 검문하는 방식”으로 바꿉니다. 사람이 직접 PASS를 적는 대신, 각 단계가 JSON 증거를 남기고 마지막 스크립트가 통과 가능 여부를 확인합니다. 34개 IA는 한 사람이 한꺼번에 보는 방식이 아니라, 여러 에이전트가 묶음별로 나눠 보는 방식으로 바꿉니다.

Phase 5에서는 AI가 먼저 34개 IA를 훑고, 위험한 부분과 사람이 봐야 할 질문을 정리합니다. 그래서 앞 단계의 역할도 바뀝니다. Phase 2, 3, 4는 AI가 볼 수 있는 “증거 사진첩”을 만듭니다. 로딩, 빈 화면, 에러, 직접 URL, 뒤로가기, 복구 버튼까지 남겨야 AI 판단도 믿을 수 있습니다.

34 현재 IA 항목

화면, 팝업, 상태 화면까지 검수 대상입니다.

스크립트 자동 검문소

문서 영수증, 화면 증거, 보안 증거가 빠지면 통과를 막습니다.

묶음 검수 여러 에이전트 분담

IA를 6개 안팎의 묶음으로 나눠 빠짐없이 살핍니다.

AI+사람 UX 최종 판단

AI가 먼저 위험을 찾고, 사람은 판단이 필요한 질문을 확인합니다.

전체 흐름

개발자가 아니어도 어느 단계에서 무엇을 확인하는지 볼 수 있도록 나눴습니다.

0준비

기준 문서와 34개 IA 목록을 확인합니다.

0.5문서 영수증

각 IA마다 어떤 문서를 읽었는지 흔적을 남깁니다.

1목록화

검수할 화면, 팝업, 서버 경로를 한 장의 명단으로 만듭니다.

1.5나눠 맡김

IA 묶음을 만들고 에이전트별 작업 지시서를 준비합니다.

2화면 확인

브라우저로 실제 페이지가 열리고 보이는지 확인합니다.

3팝업 확인

제출 확인, 저장 경고, 분석 로딩 같은 상태를 따로 봅니다.

4접근 확인

로그인, 권한, 직접 URL, 뒤로가기, 새로고침을 점검합니다.

5AI+사람 UX

AI가 먼저 보고, 사람이 판단이 필요한 부분을 최종 확인합니다.

6리포트

PASS, FAIL, BLOCKED 같은 결과표로 모읍니다.

스크립트는 감독관 역할을 합니다

비유하면, 사람이 쓴 검사 메모 옆에서 감독관이 도장을 찍는 구조입니다. 도장 조건이 빠지면 최종 통과가 되지 않습니다.

문서 영수증 검사

문서를 읽었다면 어떤 문서에서 어떤 요구사항을 뽑았는지 남겨야 합니다.

증거 파일 검사

브라우저, 팝업, 권한, 뒤로가기 결과가 JSON으로 남아 있는지 봅니다.

최종 PASS 검사

증거가 빠졌는데 PASS라고 적힌 항목을 마지막에 막습니다.

에이전트는 조별 검사원처럼 움직입니다

34개 IA를 한 에이전트가 전부 기억해서 보는 방식은 놓치기 쉽습니다. 그래서 공개/인증, 온보딩, 작성, 피드백, 보관함/설정, 관리자/보안처럼 묶음을 나눕니다. 각 에이전트는 자기 묶음만 깊게 보고, 최종 판정은 진행 관리자와 스크립트가 합칩니다.

진행 관리자

누가 어떤 IA 묶음을 볼지 정하고, 충돌 난 결과를 정리합니다.

IA 묶음 에이전트

담당 묶음의 문서, 화면 증거, UX 위험을 보고 결과 패킷을 냅니다.

최종 검증

에이전트가 PASS라고 해도 증거가 부족하면 최종 PASS가 되지 않습니다.

단계별로 쉽게 보기

Phase 0

먼저 기준표를 정합니다

docs/sitemap.md, docs/IA/README.md, docs/flow/user-flow.md를 기준으로 삼습니다.

Phase 0.5

문서 읽기 영수증을 남깁니다

각 IA마다 읽은 문서, 뽑은 요구사항, 문서 충돌 여부를 doc-receipts.json에 남깁니다. 이 영수증이 없으면 최종 통과가 안 됩니다.

Phase 1

검수 대상 명단을 만듭니다

34개 IA가 전부 있는지, 실제 코드에 맞는 주소가 있는지 확인합니다. 결과는 ia-manifest.json과 source-map-results.json으로 남깁니다.

Phase 1.5

IA를 묶음으로 나눠 맡깁니다

agent-dispatch-plan.json으로 공개/인증, 작성, 피드백, 관리자/보안 같은 묶음을 만듭니다. 각 묶음은 작업 지시서와 결과 보고서를 남겨야 합니다.

Phase 2

브라우저로 화면을 엽니다

모바일, 태블릿, 데스크톱 크기에서 제목과 주요 버튼이 보이는지 봅니다. 빈 화면, 에러, 로딩, 입력 안내 같은 상태도 AI가 볼 증거로 남깁니다.

Phase 3

팝업과 대기 상태를 봅니다

제출 확인, AI 분석 로딩, 자동저장 경고, PDF 내보내기 같은 화면 안의 화면을 확인합니다. 열기 전, 열린 뒤, 닫은 뒤 상태도 AI가 볼 증거로 남깁니다.

Phase 4

외부 접근과 권한을 봅니다

직접 URL, 다른 사람의 결과 id, 관리자 주소, 로그아웃 뒤로가기 같은 위험한 진입을 확인합니다. 사용자가 어디에 있는지, 어디로 돌아가면 되는지 안내 문구도 증거로 남깁니다.

Phase 5

AI가 먼저 UX를 보고, 사람이 최종 확인합니다

AI는 앞 단계에서 모은 JSON 증거와 에이전트 결과 패킷을 읽고 모든 IA의 리뷰 카드를 만듭니다. 사람은 AI가 제시한 질문을 중심으로 최종 UX 판단을 합니다.

  • 첫 제목만 봐도 현재 위치를 아는가?
  • 뒤로가기와 직접 URL 진입이 자연스러운가?
  • AI 추천과 피드백의 근거와 한계가 보이는가?
  • 에러가 “무슨 일 / 왜 문제 / 고치는 법”을 알려주는가?
  • 모바일, 키보드, 모달 포커스가 안전한가?

결과표는 신호등처럼 봅니다

PASS

문서, 화면, 흐름, 증거가 맞습니다.

PARTIAL

큰 줄기는 되지만 증거나 세부 UX가 부족합니다.

FAIL

사용자 혼란, 접근성 문제, 보안/정책 위험이 있습니다.

DEFERRED

문서상 나중 범위라 지금 실패로 보지 않습니다.

DOC-GAP

문서가 결정을 안 해서 판단할 수 없습니다.

BLOCKED

계정, 데이터, 환경이 없어 검수할 수 없습니다.

여러 에이전트가 어떻게 나눠 보나요?

이 부분은 한 명의 리뷰어 목록이 아니라, 검수 공장 라인처럼 보면 됩니다. 진행 관리자가 IA 묶음을 나누고, 여러 에이전트가 동시에 보고, 마지막에는 스크립트가 증거를 대조합니다.

1. 진행 관리자

IA를 묶음으로 나누고, 작업 지시서와 최종 병합을 책임집니다.

2. 자동화 담당

스크립트와 테스트로 문서, 화면, 보안 증거가 빠졌는지 확인합니다.

3. IA 묶음 에이전트 1~6

공개/인증, 작성, 피드백, 설정, 관리자처럼 나뉜 묶음을 동시에 봅니다.

4. 재검토 에이전트

서로 말이 다르거나 위험한 IA를 한 개씩 다시 확인합니다.

5. AI UX 종합 리뷰어

묶음 에이전트 결과와 화면 증거를 합쳐 UX 위험과 질문을 정리합니다.

6. 사람 UX 리뷰어

문구, 화면 이해도, 모바일 체감, 신뢰감처럼 사람 판단이 필요한 부분을 봅니다.

7. 보안/데이터 에이전트

권한, 세션, 다른 사람 데이터 노출, 관리자 접근을 깊게 봅니다.

8. 운영/정책 에이전트

결제, 알림, 개인정보, 오류 복구 문구가 문서와 맞는지 봅니다.

9. 최종 검증 스크립트

에이전트 추천이 아니라 JSON 증거 기준으로 최종 PASS를 막거나 허용합니다.

최종 산출물

doc-receipts.json

각 IA마다 어떤 문서를 읽고 어떤 요구사항을 뽑았는지 남긴 영수증입니다.

ia-manifest.json

검수할 34개 IA 항목을 스크립트가 읽을 수 있게 정리한 명단입니다.

source-map-results.json

문서의 화면과 실제 코드 위치가 연결되는지 본 결과입니다.

static-results.json

문서와 코드가 서로 맞는지 본 결과입니다.

browser-results.json

브라우저로 실제 화면을 열어 본 결과입니다.

hosted-surface-results.json

팝업, 로딩, 자동저장 경고처럼 화면 안에서 뜨는 상태를 본 결과입니다.

security-navigation-results.json

로그인, 권한, 뒤로가기, 직접 URL 접근을 본 결과입니다.

agent-dispatch-plan.json

어떤 IA 묶음을 어떤 에이전트가 볼지 정리한 분담표입니다.

agent-packets/tasks/*.md

에이전트에게 주는 작업 지시서입니다. 읽을 문서, 볼 증거, 건드리면 안 되는 범위를 적습니다.

agent-packets/results/*.md

에이전트가 돌려주는 결과 보고서입니다. 추천 라벨, 부족한 증거, 질문을 남깁니다.

agent-integration-results.json

진행 관리자가 에이전트 결과를 받아들였는지, 되돌렸는지, 재검토로 보냈는지 남긴 파일입니다.

ai-ux-review.json / .md

AI가 먼저 본 UX 준비도 카드입니다. JSON이 원본 증거이고 Markdown은 사람이 읽기 쉬운 설명입니다.

manual-review.json / .md

사람이 최종 확인한 UX 판단 기록입니다.

ia-implementation-audit.json / .md

34개 IA의 최종 성적표입니다. AI 판단, AI 확신도, 사람 확인, 최종 UX 결과를 따로 남깁니다.

merge-ia-audit-results.mjs

여러 증거 파일을 모아 최종 성적표를 만드는 스크립트입니다.

validate-ia-audit-report.mjs

증거 없이 PASS가 적힌 항목을 마지막에 막는 스크립트입니다.

최종 성적표는 네 칸으로 나눕니다

AI UX 결과

AI가 먼저 본 UX 준비 상태입니다.

AI 확신도

AI 판단을 얼마나 믿을 수 있는지 표시합니다.

사람 확인

사람이 꼭 봐야 하는지, 이미 확인했는지 적습니다.

최종 UX 결과

증거와 사람 판단을 합친 최종 결론입니다.

가장 중요한 안전장치

  • 페이지가 열린다고 곧바로 통과가 아닙니다.
  • 문서 영수증이 없으면 통과가 아닙니다.
  • AI가 봤다고 사람 판단이 사라지는 것은 아닙니다.
  • 에이전트가 PASS라고 추천해도 최종 PASS가 아닙니다.
  • 에이전트 결과 보고서가 없으면 해당 IA는 막힌 상태로 둡니다.
  • 스크린샷이나 브라우저 증거가 없으면 통과로 두지 않습니다.
  • 최종 PASS는 손으로 적는 값이 아니라 스크립트가 계산하고 검증하는 값입니다.
  • Markdown 설명과 JSON 결과가 다르면 JSON과 검증 스크립트를 우선합니다.
  • 모달은 부품 파일만 보지 않고 실제 열리는 화면에서 확인합니다.
  • 결제와 알림처럼 아직 미룬 기능은 실제 동작하는 것처럼 말하면 안 됩니다.

용어집

IA

화면 목록과 화면 안 구조입니다.

Manifest

문서 영수증

어떤 문서를 읽고 어떤 요구사항을 뽑았는지 남긴 기록입니다.

IA 묶음

비슷한 화면을 한데 묶어 한 에이전트가 담당하게 만든 작은 검수 단위입니다.

작업 지시서

에이전트에게 “이 문서와 이 증거를 보고, 이 범위만 확인해줘”라고 주는 안내서입니다.

결과 패킷

에이전트가 검수 뒤에 돌려주는 보고서입니다. 추천 라벨과 부족한 증거가 들어갑니다.

JSON

스크립트가 읽기 쉬운 정리 파일입니다. 최종 검문소의 기준 자료입니다.

검증 스크립트

빠진 증거나 잘못된 PASS를 자동으로 잡는 검사 프로그램입니다.
