잔여 우려 (accepted with reason)

Codex round 2에서 짚었으나 본 PR 범위 밖으로 분리한 항목들. 각각 후속 작업으로 추적.

  1. ① fixture sync drift
    fixture가 checker 룰과 같이 유지 안 되면 "두 번째 정본"처럼 썩을 위험. 완화: 자동 실행 스크립트가 회귀 잡음. 장기적 sync는 별도 운영.
  2. ② skipped 사유 남용 ("internal refactor — no visual change" 등)
    현 시점 운영 데이터 없음. 1-2개월 후 별도 PR로 사유 빈도 감사 (degraded-mode 감사와 묶기 가능).
  3. ③ 디자인 측 합의 미완
    최소 PASS 기준은 plan/review-gates에 명시했으나 디자인 owner 1명 비동기 확인 미실행. 첫 UI PR 진입 전 ping 필요.

  1. ① 4개 체크 최소 PASS 기준이 디자인팀 의도와 맞나? (Tokens · Components · A11y · Responsive)
    정본(02-global-styles, 03-patterns, 07-review-checklist, 08-theme)을 그대로 따랐어요. 디자인팀 ping 필요.

    src/app/**, src/components/**, src/features/**, src/lib/ui/**, src/styles/**, *.css, *.scss, theme*, tailwind.config.*, postcss.config.*, public/icons|images/**, globals.css — 추가/제외 필요한 곳?

    types-only는 자동 면제 아니고 사유 의무로 보강했어요.
  4. ④ 게이트 위치 (Architecture Pass 후, QA Gate 전) 적절?
    UI 구현 완료 후 사전 점검 → 실행 검증(QA) 전. 그 사이 위치가 자연스러움.
  5. ⑤ PR A + PR B 묶어서 커밋할까요, 별도로 커밋?
    현재 working tree에 둘 다 stage 가능. 묶으면 history 한 단위, 분리하면 추적 명확.
