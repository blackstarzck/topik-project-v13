② 다른 AI 검토 (Cross-model review) — 시간 순서

한 AI가 짠 코드를 다른 AI가 검토하는 절차. 결과에 따라 분기되는 흐름을 시간 축으로 그렸습니다.

sequenceDiagram
  autonumber
  participant A as Implementer
(Codex 또는 Claude)
  participant R as Reviewer
(다른 AI)
  participant L as 작업 일지
  participant U as 사용자

  A->>R: 코드/계획 검토 요청
  R-->>A: PASS · CONCERN · FAIL

  alt PASS
    A->>L: "Cross-model review: PASS" 기록
    A->>A: 마무리 관문 진행
  else CONCERN
    A->>L: 우려 사항 + "수용 사유" 기록
    A->>A: 마무리 관문 진행
  else FAIL
    Note over A,R: 라운드 시작 (기본 3 / 안내문 변경 4-5)
    loop 라운드
      A->>A: 모든 층 수정
(요약·작업표·세부·검증)
      A->>R: 같은 검토자에게 재검토 요청
      R-->>A: PASS or FAIL
    end
    opt 5라운드 초과
      A->>U: 사용자에게 올림 (escalate)
      U-->>A: 결정
      A->>L: 결정 + 사유 기록
    end
  end

  Note over R: Reviewer 호출 자체가 불가하면
"Cross-model review: degraded — 사유"
를 일지에 기록하고 self-review로 진행

의견 갈리면 정량 기준 → 정성 trade-off → 사용자 escalate 순. 결정은 무조건 일지에 영구 기록.

③ 막혔을 때 5종 분류 (Fallback)

정상 경로에서 무언가 막히면 우선 어느 종류의 막힘인지 분류해야 합니다. 분류에 따라 대응이 다릅니다.

stateDiagram-v2
  direction LR
  [*] --> Normal: 작업 진행
  Normal --> Blocked: 막힘 발생

  state Blocked {
    [*] --> Classify
    Classify --> FailClosed: 충돌·파괴·비밀 노출·
보안 불확실·승인 누락
    Classify --> Degraded:  도구·리뷰어·테스트러너 없음
    Classify --> Recover:   컨텍스트 끊김·
일지 stale
    Classify --> RetryOnce: 일시적 네트워크·CLI 오류
    Classify --> Reassign:  자식 AI 결과 없음·
scope 충돌
  }

  FailClosed --> Stop: 즉시 중단
사용자 결정 대기
  Degraded   --> Normal: 사유 + 임시 절차
일지 기록
  Recover    --> Normal: 안내문·일지·문서
다시 읽고 재구축
  RetryOnce  --> Normal: 1회 재시도 성공
  RetryOnce  --> Stop:   2회 실패
  Reassign   --> Normal: 재위임 또는 부모가 회수

  Stop --> [*]
  Normal --> [*]: 작업 완료

Fail-closed 5종(충돌·파괴·비밀·보안·승인)은 무조건 즉시 중단. 나머지는 흔적을 남기고 정상 경로 복귀.

④ 멀티 에이전트 위임 — Main session ↔ Child agents

Phase 단위 큰 작업이나 독립 task가 2개 이상일 때 작동합니다. ①의 "Phase 단위" 차선에서 이쪽으로 빠집니다. 핵심 원칙: Main session이 모든 결정·일지의 유일한 소유자이고, 자식이 가진 hidden context는 신뢰하지 않습니다. 자식은 bounded task packet만 받고, 결과는 result packet으로 반환해야 합니다.

A. 전체 packet 사이클 — 작업 시작부터 마무리까지

sequenceDiagram
  autonumber
  participant U as 사용자
  participant M as Main session
(coordinator · 일지 owner)
  participant L as 작업 일지
  participant CA as Child A
(독립 write scope)
  participant CB as Child B
(다른 write scope)
  participant R as Reviewer
(다른 AI)

  U->>M: 작업 요청
  M->>L: 일지 생성 + 차선 결정
  M->>M: 계획서 작성 (Out of Scope · SBU)
작업표에 Subagent-eligible Y/N + 사유

  par Y로 마크된 독립 작업 병렬 위임
    M->>CA: Task Packet
(범위·제약·검증·일지 경로 13필드)
    M->>CB: Task Packet
(다른 write scope)
  and N 작업은 메인이 직접
    M->>M: 단일 owner로 실행
  end

  par 자식 동시 작업
    CA->>CA: 수신 범위 안에서만 작업
    CA-->>M: Result Packet (12필드)
  and
    CB->>CB: 작업
    CB-->>M: Result Packet
  end

  M->>M: Integration Checklist 5단계 (아래 C 참조)
  alt 모든 체크 PASS
    M->>L: 두 결과 + 통합 결정 기록
  else 누락·충돌·실패
    M->>M: Reassign 또는 메인이 직접 수정
    M->>CA: (옵션) 재위임 Task Packet
  end

  M->>R: 통합 결과 검토 요청
  R-->>M: PASS · CONCERN · FAIL
  M->>L: Cross-model review 결과 기록
  M->>U: 마무리 보고

  Note over M,L: Main이 결과를 통합·기록하기 전에는
"완료"라고 말할 수 없음.
자식의 hidden context는 신뢰 X.

위임은 par/and 블록으로 병렬. 자식 결과가 없거나 scope 위반이면 alt 분기로 Reassign. 마무리 보고는 통합 끝난 뒤에만.

D. Child agent 입장에서 본 상태 머신

stateDiagram-v2
  direction LR
  [*] --> Received: Task Packet 수신
  Received --> Working: 범위 확인 + 시작
  Working --> Returned: Result Packet 작성
  Working --> Blocked: blocker 발견
  Blocked --> Returned: blocker 명시한
Result Packet 반환
  Working --> Timeout: 응답 없음
  Working --> ScopeConflict: 다른 자식과
write scope 충돌

  Returned --> Integrated: 메인 통합 체크 PASS
  Returned --> Reassigned: scope 위반·정보 부족
  Timeout --> Reassigned: 메인이 회수
  ScopeConflict --> Reassigned

  Reassigned --> Received: 새 Task Packet (tighter scope)
  Integrated --> [*]

자식은 결과가 비더라도 blocker를 명시한 Result Packet은 꼭 반환해야 함. "조용한 실패(silent failure)" 금지.

나오는 단어 풀이

차선 (lane)작업 종류별 정해진 경로. 5개: 가벼움 · 버그 · 새 기능 · UI · Phase.
작업 일지 (ledger)이번 작업을 누가/왜/어떻게 했는지 적은 파일. 안내문 건드리면 필수.
간단 명세서 (Light Spec)Phase 시작 전 1쪽 명세 — 6섹션 필수.
계획 사전 검토 통과 관문코드 짜기 전, 계획 자체를 다른 AI에게 검토받기.
TDD실패 테스트 먼저 → 통과 → 정리. 예외 4종은 사유 기록.
다른 AI 검토 (Cross-model review)한 AI가 짠 걸 다른 AI가 검토. 시야의 빈틈을 메우기 위함.
임시 통과 (degraded)리뷰어 호출 불가 시 사유 적고 일단 통과하는 안전장치.
구조 마무리 점검 (Architecture Pass)Phase 완료 시 로직 위치·폴더명·중복 마지막 점검.
화면 QAUI 바뀌면 로컬 실행 + 클릭 + 반응형 직접 확인.
Git 공개 결정 4지선다no-commit · local-commit · push-and-pr · blocked 중 명시.
Fail-closed5가지 상황(충돌/파괴/비밀/보안/승인)에서 무조건 중단.
task / result packet부모 AI ↔ 자식 AI 사이의 작업 명세와 결과 보고.
