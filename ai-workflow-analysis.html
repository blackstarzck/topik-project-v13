1. 한 줄 요약

설계 품질은 매우 높지만, 강제성은 전부 "프롬프트(자연어)" 레벨이다. Hook·CI 등 시스템 레벨로 차단하는 장치는 사실상 PR 템플릿 1개뿐이며, 나머지는 모두 AI 자체의 지시 이행 능력에 의존한다. 본 워크플로우의 "강제성"은 지침 강도 + 템플릿 + 자기 점검(self-attestation)의 조합이다.

설계

3-tier 문서, 라우팅 인덱스, 작업일지(ledger), 에이전트 패킷, 리포트 템플릿, Git 공개 결정 gate, fallback 매트릭스까지 완비.

강함

스킬 인프라

Superpowers + GStack 합산 61개 스킬이 .claude/skills/에 프로젝트 로컬로 설치됨. 호출 경로는 명시되어 있음.

강함

강제성

.claude/settings.json이 없음. PreToolUse/Stop hook 0개. CI 워크플로 없음. PR 템플릿만 시스템 레벨 gate.

약함 (자연어 의존)

2. 전체 구조: 3-tier 문서 계층

워크플로우는 "계약 → 라우팅 → 절차"의 3단 분리로 설계되어 있어, 각 문서가 짧고 책임이 명확하다.

계층파일역할크기/특징
① 계약 AGENTS.md · CLAUDE.md "무조건 지켜야 하는 것"만. 시작 절차, 비협상 규칙, 완료 gate. 64줄. 호스트별 분리 (Codex / Claude Code).
② 라우팅 docs/agent-index.md 사용자 목표 → 읽어야 할 문서 매핑. "Goal-to-Doc Routing" 표가 핵심. 15개 index group + active/legacy 구분.
③ 절차 docs/ai-development-workflow.md 실제 실행 단계. Mermaid 다이어그램 + 7개 섹션(0~7). 375줄. Fallback 매트릭스 포함.
설계 미덕: AGENTS.md를 의도적으로 짧게 유지하고, 세부는 harness-and-skills.md로 분리. → 신규 AI 세션이 시작 시 읽어야 하는 양을 최소화함. 컨텍스트 윈도우 절약에 유리.

4. 보조 인프라: Ledger / Packets / Templates

Context Ledger

docs/ai-workflow/runs/YYYYMMDD-HHMM-task-slug.md

11개 필드: Run Metadata, Task, Docs Consulted, Decisions(append-only), Active Files, Agent Assignments, Child Result Packets, Verification State, Fallback State, Consistency, Risks.

현재 누적된 ledger: 10개 (2026-05-18 ~ 2026-05-19). 워크플로우가 이미 여러 회 실주행되었다는 증거.

Agent Packets

Task Packet (위임 시) / Result Packet (회수 시) 두 양식.

필수 필드: Objective, Accepted scope, Out of scope, Exact read/write scope, Files not to touch, Required verification, Expected output. → "숨은 컨텍스트"를 허용하지 않음.

Report Template

9개 섹션: Task, Docs Consulted, Workflow Gates, Implementation Summary, Multi-Agent, Verification, Git Publication Decision, Fallbacks, Risks, Completion Decision.

"무엇을 했다"가 아니라 "어떤 증거로 했다"를 강제하는 구조.

Git Publication Decision Gate

구현 완료와 "publish 안전성"을 분리. 4가지 outcome: no-commit / local-commit / push-and-pr / blocked.

Conventional Commits + Lore trailer(Constraint, Rejected, Confidence, Scope-risk, Directive, Tested, Not-tested, Publication-decision, Review, Ledger) 의무.

Fallback 매트릭스

실패 유형을 5가지로 분류하고 각각의 대응을 못 박는다. → AI가 "예외 상황"에서 임의 판단하지 못하게 막는 안전장치.

분류대표 사례대응
Fail closeddoc 충돌, 파괴적 작업, 시크릿 노출 위험, 보안 불확실중단 + 사용자 결정 대기
Degraded modeGStack 불가, 브라우저 자동화 불가수동 체크리스트 + ledger 기록
Recover컨텍스트 압축, ledger 분실AGENTS.md → workflow → ledger 재구축
Retry once일시적 네트워크/CLI 오류1회 재시도 후 보고
Reassign하위 에이전트 타임아웃, 결과 패킷 누락메인 세션이 회수하거나 더 좁게 재위임

5. 스킬 계층: Superpowers + GStack

.claude/skills/ 아래 61개의 스킬이 프로젝트 로컬로 설치됨. 글로벌 스킬은 명시적으로 금지.

  • using-superpowers — 세션 시작 필수

  • test-driven-development — 코드 변경 시 의무
  • systematic-debugging
  • requesting-code-review / receiving-code-review
  • verification-before-completion
  • finishing-a-development-branch
  • subagent-driven-development, dispatching-parallel-agents

GStack (게이트 + 실무 작업)

  • office-hours — 신규 범위 brainstorm
  • plan-ceo-review / plan-eng-review / plan-design-review / plan-devex-review

  • qa / qa-only — 브라우저 QA

6. 강제성 분석 — 진짜로 강제되는가?

"강제성"을 (A) 시스템이 기술적으로 차단/검증하는 것 (B) 프롬프트가 강한 어조로 지시해 AI가 자기 점검하는 것으로 나눠 평가한다.

A. 시스템 레벨 강제 (Hard enforcement)

장치존재 여부비고
.claude/settings.json hooks (PreToolUse, PostToolUse, Stop, UserPromptSubmit) 없음 파일 자체가 존재하지 않음. settings.local.json에 PowerShell 권한 1줄만 있음.
CI 워크플로 (.github/workflows/) 없음 .github/에 pull_request_template.md 1개만 존재.
Pre-commit / Git hooks 없음 .gitmessage는 있으나 (commit 템플릿) 검증 기능 아님.
PR 템플릿 — Docs Consulted, Review, Verification, Git Publication Decision, Risks 강제 있음 GitHub UI가 자동 삽입. 현재 시스템 레벨 강제는 사실상 이 하나뿐.
커밋 메시지 컨벤션 (Conventional Commits + Lore trailers) 문서로만 린트 도구 없음. AI 자기 준수에 의존.

B. 프롬프트 레벨 강제 (Soft enforcement)

장치강도메커니즘
CLAUDE.md 자동 로드 강함 모든 Claude Code 세션 시작 시 컨텍스트에 자동 주입.
AGENTS.md "Non-Negotiable Rules" 섹션 강함 "Do not", "stop and report", "Fail closed" 등 명령조. AI가 식별하기 쉬움.
완료 gate 자기 점검 (8개 조건) 중간 AI가 스스로 체크. 실제 검증은 보고서 필드 기입 여부로만 확인 가능.
"Docs consulted" 필드 의무화 중간 보고서/계획에 필드 있음. AI가 비워두면 사용자가 보고 잡아야 함.
Ledger를 append-only 결정 테이블로 강제 중간 구조가 단순해 누락 시 빈 표가 명확히 드러남.
using-superpowers 스킬의 "EXTREMELY-IMPORTANT" 어조 강함 스킬 본문이 "rationalize your way out of this" 같은 강한 표현으로 우회를 봉쇄.
결론: 본 워크플로우의 강제성은 "코드로 막는 것"이 아니라 "보고서 필드를 비우지 못하게 하는 것"이다. AI가 정직하게 자기 점검하면 잘 작동하고, 게으르게 답하면 사용자가 보고서 필드의 빈 칸으로만 잡아낼 수 있다.

7. AI가 놓치기 쉬운 지점

설계가 좋아도 시스템 차단이 없으면, 다음 지점들은 실제 운영에서 자주 빠진다.

지점왜 놓치기 쉬운가현재 상태
using-superpowers 호출 "이 작업은 간단하니 생략해도 되겠지" 판단 스킬 본문의 강한 어조가 막고 있으나 100% 아님
agent-index를 거치지 않고 docs를 직감으로 선택 익숙한 문서명이 떠오를 때 인덱스를 건너뜀 출력에서 "Docs consulted" 필드만 보면 알아챌 수 있음
Ledger 갱신 누락 (실행 중간 결정들) 구현에 몰입하면 ledger 업데이트가 후순위로 밀림 완료 후 한꺼번에 채워 넣는 패턴 발생 가능
TDD RED 단계 생략 "테스트 표면이 없어서" 면제 조건을 광범위 해석 현재 src/·package.json 없음 → 거의 모든 작업이 면제로 빠질 수 있음
plan-eng-review / plan-design-review 스킵 "이 정도면 risk 없다"는 자체 판정 실제 호출 여부를 검증하는 장치 없음
Child agent 결과 패킷 통합 누락 여러 subagent를 띄우고 요약만 보고 진행 AGENTS.md에 "trusting hidden child context" 금지로 명시되어 있으나 프롬프트 레벨
Git Publication Decision 기록 누락 commit 후 보고서에 빠지기 쉬움 PR 템플릿이 잡아주지만, local-commit/no-commit인 경우는 PR이 안 열리므로 빠짐
Fallback 사용 후 보고 누락 "되긴 됐으니까" 그대로 진행 보고서에 Fallback 섹션이 있어 빈 칸이 보이긴 함

8. 실제로 작동할까? 종합 평가

잘 작동할 근거

  • 이미 10개의 run ledger가 누적 → 실주행 이력 있음
  • 3-tier 분리로 신규 세션의 진입 비용이 낮음
  • 스킬이 프로젝트 로컬에 설치되어 환경 표류가 적음
  • 보고서 템플릿의 빈 필드가 자기 점검을 거의 강제함
  • Codex/Claude 페어링 가정이 self-review 함정을 줄임
  • 한국어/영어 병용으로 비개발자 사용자도 검수 가능
  • Fallback 매트릭스로 예외 처리까지 명문화

실패할 수 있는 시나리오

  • 사용자가 보고서를 자세히 읽지 않으면 누락이 흘러감
  • "tiny edit" 면제 조항이 광범위 해석되면 ledger가 사라짐
  • 현재 src/ 없음 → TDD 면제가 디폴트가 될 위험
  • 여러 세션 분리 시 ledger를 다른 AI가 못 찾으면 컨텍스트 분실
  • 스킬 미설치 환경(Codex/다른 호스트)에서 fallback이 약화될 수 있음
  • 커밋 메시지 trailer 린트 없음 → 점진적 표준 침식 가능
종합: "교범으로서는 상위 1%, 강제 장치로는 중간 정도"의 워크플로우. AI가 지시를 잘 따르면 큰 문제 없이 굴러갈 수 있는 수준의 완성도이며, 실제로 그렇게 운영되고 있다는 흔적이 ledger에 남아 있다. 단, "AI가 절대 빠뜨릴 수 없게" 만들고 싶다면 hook/CI 레이어가 필요하다.

9. 보완 제안 (강제성을 끌어올리려면)

대상제안난이도
.claude/settings.json hooks PreToolUse(Edit, Write): 첫 Edit/Write 전에 ledger 파일 존재 여부 체크.
Stop: 응답에 "Docs consulted" 문자열이 포함되었는지 검증. 		낮음
CI 워크플로 (.github/workflows/pr-check.yml) PR 본문에 Docs Consulted / Review / Verification / Git Publication Decision 5개 섹션이 비어있지 않은지 grep. 낮음
커밋 메시지 린트 commitlint + Lore trailer 검증 스크립트. .gitmessage 템플릿과 연동. 중간
Ledger 갱신 강제 각 커밋 메시지의 Ledger: trailer가 실제 존재 파일을 가리키는지 git hook으로 검증. 중간
스킬 호출 가시화 보고서 템플릿에 "스킬 호출 로그" 필드 추가 + 사용자가 트랜스크립트로 교차 검증. 낮음
TDD 면제 좁히기 "src/ 부재" 시점 한정 면제임을 AGENTS.md에 명시. src/ 등장 즉시 면제 해제. 낮음
가장 ROI가 높은 한 가지: .claude/settings.json에 Stop hook을 추가해 최종 응답에 Docs consulted·Git Publication Decision 두 키워드가 없으면 차단하는 것. 이 한 줄짜리 검증이 현재 누락 위험의 상당 부분을 시스템 레벨로 끌어올린다.
