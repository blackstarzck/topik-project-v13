# Decision Pack — Phase 7 사전 결정

## Decision 1 · 인증 UI 가입 방식

**무슨 일?**  
인증 4개 화면이 비어 있습니다. 랜딩, 회원가입, 로그인, 비밀번호 재설정이 먼저 채워져야 합니다.

**왜 결정해야?**  
가입 방식이 정해져야 온보딩, 대시보드, 실제 사용자 QA가 시작됩니다. 여기서 막히면 골든 패스가 0단계에서 멈춥니다.

**옵션 비교**  
A: 이메일+비번 기본, 매직링크 옵션. 표준이고 Supabase 기본 흐름과 맞음.  
B: 매직링크만. 빨라 보이지만 매번 이메일 확인이 필요하고 SMTP 범위와 부딪힘.  
C: 이메일+비번만. 가장 단순하지만 매직링크 UX를 버림.  
D: 소셜 로그인 우선. 한국 시장에는 좋지만 OAuth 설정과 정책 검토가 커짐.

**Codex 권장**: A  
**이유**: IA가 이메일/비밀번호, 비밀번호 재설정, 소셜 분기를 모두 요구합니다. A가 MVP에서 가장 안전하고, Supabase Auth 기본 기능을 가장 많이 재사용합니다.  
**조심할 점**: B는 “1일짜리”처럼 보이지만 이메일 전송 인프라가 먼저 필요합니다. 고르면 Tier 2로 미룬 SMTP 문제를 Phase 7 안으로 끌고 옵니다.

## Decision 2 · 글쓰기 53번 UI 범위

**무슨 일?**  
53번은 도표 분석 장문입니다. 지금처럼 큰 textarea 하나로는 문제 자료, 문단 구조, 원고지 감각을 못 줍니다.

**왜 결정해야?**  
53번은 TOPIK II 쓰기 핵심 고난도 문제입니다. 이 화면이 부실하면 “쓰기 학습 앱”의 본질이 약해집니다.

**옵션 비교**  
A: `LongFormEditor` 새 컴포넌트. 3탭, 원고지 미리보기, 도표 영역까지 spec 100%.  
B: 기존 `WritingEditor` 안에서 53번만 분기. 빠르지만 파일이 커지고 유지보수가 나빠짐.  
C: 다음 phase로 미룸. 시간은 안 쓰지만 53번 학습 효과가 크게 깨짐.

**Codex 권장**: A  
**이유**: 53번은 51/52와 성격이 다릅니다. 별도 컴포넌트로 빼야 54번 장문 확장까지 덜 꼬입니다.  
**조심할 점**: C는 “0일”이라 좋아 보이지만 실제로는 핵심 학습 화면을 30%짜리로 출시하는 선택입니다.

## 우선순위

더 많이 막는 결정은 **Decision 1 · 인증 UI**입니다.  
인증이 안 되면 가입, 로그인, 온보딩, 대시보드, 실제 사용자 기준 QA가 전부 막힙니다.

Decision 2는 학습 품질을 크게 좌우합니다. 다만 인증보다는 뒤 단계입니다.

## 한 줄 요약

**“인증은 A안, 53번은 A안”** → 그럼 Phase 7 plan으로 진입.
